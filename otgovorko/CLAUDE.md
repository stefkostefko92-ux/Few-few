# CLAUDE.md — Отговорко (otgovorko)

Поддръжката на продуктите на Carbon Stealth VCC:

- писмото на клиента идва през **Brevo входяща поща** (webhook);
- Отговорко го записва шифровано, класифицира го и пише **чернова** на отговор през Claude във **Vertex AI в ЕС**;
- собственикът чете, поправя и праща от своята поща.

**Отговорко не праща нищо** (v1). Ползва го само собственикът: парола + TOTP + IP allowlist в nginx.
Спецификацията е в `SPEC.md`. Самостоятелен продукт — `cd otgovorko/` за всичко.

## Стек

- Node ≥22 · TypeScript strict (ESM, `NodeNext`) · Express 5 · Zod 4
- Prisma 6 + PostgreSQL 16
- `@anthropic-ai/vertex-sdk` (само ЕС регион)
- argon2id · jose (JWT в httpOnly бисквитка) · pino
- тестове `node:test` през tsx
- панел: статичен HTML + ванилов JS (`public/`), без билд
- порт **4380**

## Команди (гейтът)

```bash
npm ci
npm run gate        # prisma generate + prettier + typecheck + unit тестове + build — „готово“ = зелено
TEST_DATABASE_URL=postgresql://…/otgovorko_test npm run test:integration   # шифроване в базата, идемпотентност, срок
npm run dev         # локално (иска .env по .env.example)
npm run owner:create  # след build — единственият акаунт; паролата се пита интерактивно
```

## Layout

- `src/inbound/brevo.ts` — парсерът на Brevo inbound. Схемата е снизходителна; лош запис се пропуска. Прикачените файлове се пазят само по име.
- `src/tickets/` — хранилището:
  - `classify.ts` — класовете BG/EN/IT, `RISKY` и `NO_AI`;
  - `types.ts` — договорът `TicketStore`;
  - `memory.ts` — тестове;
  - `prisma.ts` — шифровано с `DATA_KEY`;
  - `retention.ts` — срокът.
- `src/draft/` — черновата:
  - `prompt.ts` — писмото е данни в `<писмо>`, нула инструменти;
  - `guard.ts` — канарче, чужд адрес, чужда връзка, HTML;
  - `model.ts` — Vertex;
  - `worker.ts` — на всеки 5 s, 3 опита, срокът на всеки час.
- `src/http/` — HTTP слоят:
  - `inbound-routes.ts` — webhook-ът: таен път + Bearer, временен провал = **429**;
  - `api-routes.ts` — панелът;
  - `app.ts`;
  - `guards.ts` — Origin + сесия;
  - `auth-routes.ts`.
- `src/auth/` — копие от Ловеца (продуктите не споделят код).
- `deploy/nginx/` — хостът е зад allowlist; публичен е само POST на `/inbound/brevo/<таен път>`.

## Инварианти (не ги отслабвай)

- **Без изпращач.** В `src/` няма `fetch(`, SMTP, nodemailer или Brevo `/smtp`. `tests/panel.test.ts` го проверява. Единствената мрежа е моделът.
  - Пращането е решение на собственика (SPEC §2). Brevo не приема `In-Reply-To`/`References`, а кликовете не се изключват за отделно писмо.
- **Писмото е данни, не инструкции.**
  - То е в блок `<писмо>` с екраниран разделител. Нула инструменти.
  - Изходът минава през `checkDraft`. Отказаната чернова не се пази.
- **Vertex само в ЕС.** `EU_REGIONS` е изричен списък; Лондон, Цюрих и `global` не стартират.
- **`dsar`, `legal`, `spam` не стигат до модела.** Рисковите класове (`payment`, `complaint`, `dsar`, `legal`) искат `confirmRisk`.
- **Webhook-ът:**
  - грешен път → 404, грешен Bearer → 401, провал на базата → **429**. Brevo опитва пак само при 429; 4xx и 5xx изхвърлят писмото;
  - идемпотентност по SHA-256 на Message-ID.
- **Шифроване в покой.** Подател, тема, текст, чернова и образци са шифровани с AES-256-GCM (`DATA_KEY`). Интеграционният тест търси открит текст в базата.
  - **`DATA_KEY` не се сменя** без план, иначе старите писма стават нечетими.
- **Срок 180 дни** (`RETENTION_DAYS`, 30–365) — за писмата **и** за образците. Работникът трие на всеки час.
- **Образците са обезличени** (текст от собственика, не копие) и черновата не бива да ги повтаря (`sample_echo`, 8+ думи).
- **Webhook-ът проверява пътя и токена ПРЕДИ да прочете тялото**; компресирано тяло → 415.
- **Изтриване по искане** (`DELETE /api/tickets/:id` с `confirm: true`) и търсене по подател (`?from=`).
- **Логовете** са само с id и код: без адреси, теми и текст.

# BGPP/ — БГ Държавни предприятия (прозрачност)

Независим граждански справочник: кои са държавните предприятия в България, кой ги
контролира (принципал) и **по какъв начин влизат и излизат парите им**. Всяко
предприятие сочи към официалните регистри за проверка.

_Stack: Next.js 15 (App Router) · React 19 · TypeScript · Tailwind v3. **Без база
данни** — каталогът е типизирани TS модули в `src/data/`, целият сайт е статичен
(SSG). Root-правилата (български източник на истината, one-project-per-change,
GDPR-first) важат._

## Команди (в `BGPP/`)

```bash
npm install
npm run dev          # http://localhost:3000

# Гейтове за качество (същите като локалната проверка):
npm run lint         # ESLint (next/core-web-vitals + typescript)
npm run typecheck    # tsc --noEmit
npm test             # node:test през tsx — проверки за целостта на данните
npm run build        # next build (статичен експорт на страниците)
```

## Слой на данните (сърцето на проекта)

```
src/data/
  types.ts         # Enterprise, MoneyFlow, Subsidiary, Source и таксономиите
  enterprises.ts   # КАТАЛОГЪТ — ~68 профила + дъщерни дружества в холдингите
  sectors.ts       # 12 сектора (енергетика, транспорт, отбрана, финанси, …)
  principals.ts    # министри-принципали (кой упражнява правата на държавата)
  national.ts      # агрегатни числа за целия сектор (Годишен доклад на АППК)
```

Всеки запис може да носи `subsidiaries` (дъщерни в холдинг — ВиК, ДКК, ТЕРЕМ,
БДЖ, ББР…) и `conflicts` (структурни конфликти на интереси — in-house възлагане,
концесии, свързани лица). `national.ts` захранва страницата „Картината“.

Моделът описва **структурата** на паричните потоци (`moneyIn` / `moneyOut`),
която е устойчива във времето — **не** гони конкретни годишни суми (те се менят и
се проверяват в официалните източници). Всяко вписване има `oversight` (контрол)
и `sources` (връзки към АППК, Търговски регистър, МФ, СИГМА и т.н.).

### Добавяне/промяна на предприятие
1. Добави обект в `ENTERPRISES` (`src/data/enterprises.ts`) по типа `Enterprise`.
2. `slug` — само `[a-z0-9-]`, уникален. `sector`/`principal` — валиден ключ.
3. `moneyIn`/`moneyOut` — поне по един поток; `weight` 1 (основен) → 3 (второст.).
4. `eik` и `website` — **само ако са потвърдени** (иначе се пропускат).
5. `npm test` пази целостта (уникални slug-ове, валидни ключове, https източници).

## Конвенции

- **TypeScript, без неоправдан `any`.** Path alias `@/*` → `src/*`.
- **Данните са факти за публични институции** — проверявай преди да добавяш,
  предпочитай „без число“ пред несигурно число. Дай източник или нищо.
- **Иконите са инлайн SVG** (`src/components/icons.tsx`) — без външни зависимости.
- Само една клиентска компонента (`EnterpriseExplorer` — филтрите); всичко друго е
  сървърно и статично.
- Строг CSP в `next.config.mjs` (сайтът няма външни услуги, вход или качване).

## Инструменти (`tools/`)

- `tools/svarzanost/` — офлайн скрипт (`check.mjs`, plain Node ESM) за **сигнали за
  свързаност**: съпоставя имената на органите на държавно предприятие с
  действителните собственици на фирмите-изпълнители и маркира съвпадения (вкл.
  българската логика бащино→собствено = възможен родител–дете). **Не доказва
  роднинство** — само дава leads за проверка с първичен документ (ЗПКОНПИ, КПК,
  Търговски регистър). `tools/**` е изключен от app-линта. Пускане:
  `node tools/svarzanost/check.mjs [лица.json] [изпълнители.json]`.

## Уговорка

Проектът **не е** официален сайт на държавен орган или предприятие и **не е**
изчерпателен списък на всички дружества с държавно участие. Той е образователен
и сочи към първичните официални данни.

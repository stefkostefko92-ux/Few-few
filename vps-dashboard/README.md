# Carbon Stealth VPS Dashboard

Пълен контролен панел за VPS сървър с графичен интерфейс — управлявай **всичко** от
един екран. Един и същ панел върви на всеки от твоите VPS-и и ги контролира и двата
през federation.

> Продукт на **Carbon Stealth VCC** — част от монорепото. Нула runtime зависимости
> (само Node ≥20 stdlib). Български интерфейс.

## Какво може
| Секция | Действия |
|--------|----------|
| **Обзор** | CPU / памет / мрежа / диск на живо (SSE + canvas графики), история 1h/6h/24h/7d (на диска), uptime, ОС/ядро |
| **Продукти** | health на всеки продукт от монорепото (живи локални URL-и) |
| **Надеждност** | SLO и **бюджет за грешки** по продукт: колко от 30-дневния бюджет е останал, наличност, p95, „бавно" като отделен показател, и **скорост на изгаряне** (multi-window burn-rate по канона на Google SRE — аларма по скоростта на харчене, не по „има ли грешка сега") |
| **Аларми** | известия на телефона (Telegram / ntfy / webhook / имейл) по **симптом**: натиск върху ресурсите (PSI), steal, OOM убийства, изчерпани inode-и, препълнена опашка за връзки, паднала услуга, **Redis, който изхвърля ключове**, **услуга в рестарт-цикъл** (systemd я показва „active", защото тя наистина се вдига — и пада отново), продукт DOWN, изтичащ сертификат, **изтичащ домейн**, **липсващ/остарял бекъп**, **провалена проба за възстановяване**, провален деплой — плюс **прогноза** „дискът ще се напълни след N дни" |
| **Разследване** | какво се промени около момента на счупването: метриките, одитът, деплоите и задачите на ЕДНА времева линия, автоматично намиране на момента (CUSUM), интерактивна графика (hover за стойности, клик премества момента). Редовете ПРЕДИ момента са уликите — панелът показва съвпадения, но не твърди причинност |
| **Диагностика** | натиск (PSI), процесор по режими (вкл. **steal** — краде ли ти хостерът), диск I/O (IOPS, закъснение, заетост), TCP връзки и препълване, файлови дескриптори, inode-и, мрежа по интерфейс с изпуснати пакети, прогнози и аномалии |
| **Услуги** | systemd list/филтър, start/stop/restart/reload, статус, **групови действия**, **ресурсни лимити** (MemoryMax/High, CPUQuota, TasksMax като drop-in — продукт с теч пада сам, вместо да събори сървъра) |
| **Docker** | контейнери + stats + логове, start/stop/restart, образи, лимити на жив контейнер, **групови действия** (избери няколко → рестартирай/спри наведнъж) |
| **Compose** | цели стекове: up / down / pull / restart + логове по проект |
| **Бази** | SQLite (размер, WAL, integrity_check) + Postgres в Docker (размери, връзки); снимки с един бутон + restic |
| **Redis** | памет спрямо тавана, политика, ключове, **изхвърлени ключове** (при `allkeys-lru` Redis трие ТИХО, за да направи място — без грешка и без ред в лога), успеваемост на кеша, персистентност (AOF/RDB), BGSAVE и архив на тома |
| **Процеси** | топ по CPU/памет, kill (SIGTERM/SIGKILL) |
| **Логове** | journal tail + следене на живо, филтър по unit/приоритет, **анализ по отпечатък** — 4200 еднакви реда стават една група, а НОВИТЕ грешки (невиждани досега) излизат най-отгоре и вдигат известие |
| **Трафик** | анализ на access log-а: най-**бавни** адреси по **p95** (средното крие опашката, а тя е това, което потребителят усеща), най-искани, най-много грешки, най-активни IP-та, ботове, последни 5xx. Инкрементално четене с разпознаване на ротация; адресите се групират по форма |
| **Деплой** | **качване на ZIP направо от браузъра** (+ sha256), пускане на `autodeploy.sh` по избрани проекти с жив изход, **връщане назад към стар release** |
| **Ъпдейти** | apt upgradable, security-only / пълен upgrade като фонова задача |
| **Сигурност** | **оценка 0–100** с конкретна команда за всяка находка (SSH с пароли/root, липсващ firewall, без автоматични кръпки, услуги на 0.0.0.0, sudo без парола, празни пароли, широки права), плюс отворени портове, SSH конфиг, TLS сертификати, последни входове |
| **Целост на /etc** | отпечатък на важните конфигурации (SSH, sudoers, fstab, systemd units, Nginx, cron) и разлика спрямо него — отговаря на „какво се промени, откакто работеше" |
| **fail2ban** | кой е блокиран, по кой jail, разблокиране с един бутон |
| **Достъп по IP** | списък с разрешени адреси/CIDR пред целия панел (скенер не вижда дори формата за вход) + превключвател за режим „sudo" |
| **Firewall** | ufw: включване/изключване, добавяне и триене на правила (строга валидация) |
| **Уеб сървър** | Nginx/Caddy: преглед и **редакция на vhost-овете** с валидация преди reload (автоматичен откат), включване/изключване на сайт, `certbot renew` |
| **Бекъпи** | **томове и качени файлове** (дъмпът на базата НЕ ги покрива — при restore иначе получаваш цели данни и счупени препратки), **възраст на последния бекъп** (спрял крон не вдига грешка сам) + **планирана проба за възстановяване** (разопакова най-новия дъмп в /tmp, проверява целостта, брои таблиците — живото остава недокоснато), история на пробите, известни бекъп папки + releases за rollback |
| **Променливи (.env)** | редактор на `.env` файловете на продуктите: тайните са **скрити**, докато не ги поискаш (одитирано), записът пипа **само дадения ключ** (коментарите оцеляват, .bak копие), плюс бутон за рестарт на unit-а |
| **Домейни и TLS** | инвентар на сертификатите + **изтичане на РЕГИСТРАЦИЯТА през RDAP** (сертификатът е безполезен при паднал домейн) + **заглавки за сигурност** на живите сайтове (какво реално получава браузърът) + **проверка на DNS/CAA/порт 80 ПРЕДИ certbot** (Let's Encrypt гори лимита от 5 провала на час) и издаване, вкл. wildcard през DNS-01 |
| **Крон/таймери** | systemd таймери + crontab-и, **„пусни сега"**, резултат от последното пускане и изходът точно от него, добавяне/триене на crontab редове със строга валидация |
| **Файлове** | браузър, преглед и **редакция** (пази копие `.bak`) |
| **Терминал** | **истински интерактивен PTY** — htop, nano, sudo, цветове, Ctrl+C; всеки ред влиза в одита |
| **Еднократна команда** | бърз `bash -lc` с жив изход, без сесия |
| **Агенти** | флотът от `agents.json` + пускане на агентските инструменти (oversee, secret-scan, deploy-check…) |
| **Задачи** | всички фонови задачи + жив изход + спиране |
| **Одит** | append-only дневник на всяко действие |
| **Настройки** | двуфакторна автентикация (TOTP) |
| **Захранване** | reboot / poweroff |

Панелът е и **PWA** — инсталира се на телефона („добави към началния екран"), а
известията идват през Telegram/ntfy.

**Webhook от GitHub (по избор).** Сложи `webhook.githubSecret` в конфига и насочи
webhook-а на репото към `https://<панела>/api/webhook/github` (content type
`application/json`, същата тайна). Панелът известява за нов релийз, нов код по
`main` и провален CI. **Съзнателно НЕ деплойва** — деплоят си остава изрично
действие на човек; иначе всеки, който успее да подправи заявка, стартира код на
сървъра по път, който заобикаля решението ти. Празна тайна = маршрутът връща 404.

**Време за заявка в nginx (силно препоръчително).** По подразбиране nginx НЕ пише
колко е чакала заявката — а без това „кой адрес е бавен" няма отговор. Еднократно
в `/etc/nginx/nginx.conf` (в `http { … }`):

```nginx
log_format timed '$remote_addr - $remote_user [$time_local] "$request" '
                 '$status $body_bytes_sent "$http_referer" "$http_user_agent" '
                 'rt=$request_time ut=$upstream_response_time';
access_log /var/log/nginx/access.log timed;
```
После `nginx -t && systemctl reload nginx`. Панелът разпознава и двата формата —
без времето секцията **Трафик** работи, но показва само брой и грешки, и го казва.

Всичко се превключва между възлите (локален + peer-и) от падащото меню горе вляво.

## Бърз старт (локално, dev)
```bash
cd vps-dashboard
npm run dev          # печата еднократна парола; отвори http://127.0.0.1:7700
```

## Инсталация на сървъра
```bash
# 1) Еднократно: създава конфиг (тайни + парола), systemd услуга, вдига панела.
sudo bash deploy/install.sh
#    → админ паролата се записва в /etc/vps-dashboard/initial-admin-credential.txt (mode 600)

# 2) Публикувай зад Nginx + TLS (препоръчително + Basic-auth):
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/vps-dashboard.conf
#    смени server_name → твоя домейн, после:
sudo ln -s /etc/nginx/sites-available/vps-dashboard.conf /etc/nginx/sites-enabled/
sudo certbot --nginx -d vps1.carbonstealth.eu
#    и в config.json сложи "trustProxy": true
```
Оттам нататък деплоят е автоматичен през канона на репото: `deploy/autodeploy.sh`
разгръща и `vps-dashboard` (rsync + рестарт; конфигът/state оцеляват).

## Двата VPS-а (federation)
На **всеки** сървър инсталирай панела и им дай общ `peerToken`:
```bash
# На VPS №1 в /etc/vps-dashboard/config.json:
{ "peerToken": "<общ-дълъг-таен-низ>",
  "peers": [ { "id": "vps2", "name": "VPS Две", "url": "https://vps2.carbonstealth.eu", "token": "<общ-дълъг-таен-низ>" } ] }
# На VPS №2 — огледално, peer сочи към VPS №1.
```
Сега от единия панел превключваш към другия възел и го управляваш изцяло (вкл. живи
графики и терминал) — заявките се проксират сигурно с Bearer токена.

## Известия на телефона (препоръчително)
Най-бързият път е **ntfy** — без регистрация:
1. Инсталирай приложението ntfy и се абонирай за тайна тема (напр. `csvps-<нещо-случайно>`).
2. В панела → **Аларми** → канал ntfy → въведи темата → **Запази** → **Тестово известие**.

Telegram: направи бот при `@BotFather`, вземи `bot token` и своя `chat id`, попълни ги
там същото. Праговете (диск/CPU/памет/сертификат) също се настройват оттам.

## Сигурност
Панелът управлява целия сървър → третирай го като най-чувствителния вход. Слуша само на
`127.0.0.1`, публично само зад TLS, **включи 2FA** от Настройки.

**Режим „sudo".** Необратимите действия (захранване, терминал, деплой, възстановяване
от бекъп, запис на `.env`, firewall, показване на тайни) искат паролата **отново**,
точно преди действието. Разрешението важи 5 минути и само за текущия браузър. Това е
разликата между „някой има сесията ти" и „някой е ТИ" — сесията живее 12 часа, а
открадната бисквитка иначе значи изтрит продукт без нито едно доказване.

**Списък с разрешени адреси.** Втора врата ПРЕД паролата: адрес извън списъка не
получава дори формата за вход (важи и за статиката). Празен списък = изключено, а
панелът отказва да запише списък, който не включва текущия ти адрес — иначе една
грешка те заключва извън собствения ти сървър. Зад прокси работи само с
`trustProxy: true` и Nginx, който **презаписва** `X-Real-IP`. Пълните защити и моделът
на заплахата → [`SECURITY.md`](./SECURITY.md).

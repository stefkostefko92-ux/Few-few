# Публикатор

Instagram контент-двигател на Carbon Stealth VCC с админ панел: **чернова → човешко одобрение →
публикуване** през официалния Instagram Platform API (Instagram Login). Нашият агент Социалджията
пише черновите през подписан машинен вход; хората решават какво излиза.

## Какво прави

- **Панел на `/admin`** (сървърно рендиран, строг CSP): табло с KPI и предупреждения за токени,
  брандове, Instagram акаунти (OAuth свързване, подновяване на токен, квота), постове (списък,
  филтри, детайл с линт и дневник, редакция, одобрение/отказ, насрочване, публикуване, повторение),
  чернови от модел, потребители (7 роли), агентски ключове, одит с проверка на веригата, настройки.
- **Управлявани страници:** бранд с план (постове/седмица, дял Reels, тематични стълбове, часове,
  ключови думи, хаштаг набори, CTA, забрани, платформи за варианти, медийна библиотека). Седмичен
  **автопилот** допълва черновите до плана от реални материали, предлага час и пише варианти за
  Facebook/TikTok/LinkedIn/X. **Instagram Insights** (прегледи, обхват, взаимодействия по пост;
  обхват, прегледи, последователи, ангажирани по ден) се синхронизират всяка нощ и влизат в промпта на
  всяка следваща чернова. Страница „Представяне" на бранд; „Пусни цикъл сега" и „Синхронизирай Insights".
- **Вход за агента** `/agent/v1/*` — HMAC-подписани заявки, само четене + създаване на чернови +
  Insights (агрегати, обхват `insights:read`).
- Линт на всяка чернова: лимити на Instagram, тайни в текста, alt текст, линкове без UTM, хаштаг спам.
- Публикува снимки и Reels през двустъпковия поток на Meta: контейнер → `media_publish`.
- Насрочва през BullMQ; подновява дълготрайните токени (60 дни) и чисти сесиите с дневна задача.
- Одит с верига от хешове за всяко действие — човешко, агентско или системно.

## Какво НЕ прави

**Не създава Instagram акаунти.** Meta го забранява изрично: „You can't attempt to create accounts
… in an automated way … without our express permission" ([Terms of
Use](https://help.instagram.com/581066165581870/)). Акаунтите се създават на ръка, от човек, и се
превключват на професионални (Business/Creator). Няма ботове за ангажираност, няма скрейпване.

## Роли (7 нива)

| Роля     | Може                                                          |
| -------- | ------------------------------------------------------------- |
| OWNER    | всичко, включително потребители и ключове                     |
| ADMIN    | всичко без управление на равни/по-високи                      |
| MANAGER  | брандове, акаунти (OAuth), одобрение, насрочване, публикуване |
| REVIEWER | одобрение/отказ, насрочване, публикуване                      |
| EDITOR   | създава и редактира чернови, генерира с модел                 |
| ANALYST  | чете всичко, включително одита и настройките                  |
| VIEWER   | чете таблото, постовете, брандовете и акаунтите               |

„Четири очи": човек не одобрява собствената си чернова. Агентските чернови ги одобрява всеки ревюър.

## Първо пускане

```bash
npm ci && npm run build
npx prisma migrate deploy
OWNER_EMAIL=admin@carbonstealth.eu OWNER_NAME="Собственик" OWNER_PASSWORD='…' npm run owner:create
node dist/index.js            # HTTP + панел
node dist/queue/worker.js     # работник
```

После в панела: **Профил → включи втори фактор** (силно препоръчително за OWNER/ADMIN), създай
брандовете, свържи акаунтите, издай ключ за агента.

## Как се пуска един бранд

1. **Ръчно:** създай/вземи Instagram акаунта → превключи на **професионален** → включи 2FA.
2. **Meta App:** в [developers.facebook.com](https://developers.facebook.com/) направи приложение,
   добави **Instagram → API setup with Instagram login**, впиши `IG_REDIRECT_URI`.
3. **Разрешения:** `instagram_business_basic`, `instagram_business_content_publish`,
   `instagram_business_manage_insights` (за метриките). Със _Standard
   Access_ работят само акаунти с роля в приложението; за чужди акаунти е нужен **App Review +
   Business Verification** (Advanced Access) — започни го рано.
4. **Панел → Брандове → Нов бранд**, после **Instagram акаунти → Свържи акаунт към бранд**.
5. **Под управление:** в бранда включи „Под управление на агента", попълни плана и медийната
   библиотека (`URL | описание`, за Reels: `REELS URL | описание | cover URL`). Автопилотът минава
   всеки понеделник 06:00 (или от „Представяне → Пусни цикъл сега") и оставя чернови за преглед;
   Insights се дърпат всяка нощ в 04:30. Акаунт, свързан преди добавянето на `manage_insights` в
   `IG_SCOPES`, трябва да се свърже отново — панелът го показва.

## Агентът

1. **Панел → Агентски ключове → Нов ключ**: име, обхват (по подразбиране четене + чернови),
   брандове, разрешени IP, срок. Тайната се показва **веднъж**.
2. На машината на агента: `/etc/publikator/agent.env` (mode 600) с `PUBLIKATOR_URL`,
   `PUBLIKATOR_KEY_ID`, `PUBLIKATOR_KEY_SECRET`.
3. Агентът работи през `node tools/social/publikator.mjs` (`brands` · `accounts` · `drafts` · `draft` ·
   `insights --brand slug`). Одобрение/публикуване няма — нито в CLI-то, нито като маршрут за ключ.
   `insights` връща плана на страницата, силните/слабите постове по ангажираност и дневния тренд —
   само агрегати, никакви лични данни на последователи.

## Лимити, за които кодът знае

- **Публикации:** плаващ прозорец от 24 часа на акаунт; чете се живо от `content_publishing_limit`
  преди всяко качване и се показва на таблото.
- **Токени:** 60 дни; дневна задача подновява изтичащите; изтече ли — акаунтът иска нов OAuth.
- **Caption:** 2200 знака, до 30 хаштага. **Медия:** публичен HTTPS URL.
- **Insights:** `impressions` е спряна от Meta (v22, април 2025) — броим `views`. Метриките се
  искат на групи и неподдържана група за даден вид медия не проваля синхронизацията.

## Настройка

Копирай `.env.example` и попълни. Тайните живеят само на сървъра (mode 600), никога в репото.
`TOKEN_ENC_KEY` се ражда с `openssl rand -hex 32`.

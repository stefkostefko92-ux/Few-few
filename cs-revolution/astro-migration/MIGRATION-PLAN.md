# Carbon Stealth — Astro SSG Migration Plan

## Why Migrate?

**Current problem:** SPA React (client-side rendering) means:
- AI crawlers (GPTBot, ClaudeBot, PerplexityBot) see only `<noscript>` content
- Google can execute JS but still prefers server-rendered HTML
- Initial bundle: 289KB JS before any content is visible
- Three.js 679KB loaded on every page (lazy but still fetched)

**After Astro SSG:**
- Every page is pre-rendered HTML — zero JS needed for content
- AI crawlers see full content immediately
- Three.js loaded only on homepage as an "island"
- Admin panel stays as React island (interactive, client-only)
- PageSpeed score jumps to 95+ on all pages

## Key Decisions

1. **Static pages** (Astro components, zero JS): homepage content, services, blog, portfolio, about, contact info, geo pages
2. **React islands** (interactive, hydrated): Three.js scene, AI terminal, contact form, admin panel, cookie banner
3. **Content collections** for blog posts and services: Markdown files with frontmatter → auto-generated pages
4. **i18n via folder structure**: `/en/`, `/bg/` prefixes with JSON string files

## Migration Steps (3-5 sessions)

### Session 1: Project setup + homepage
- `npm create astro@latest`
- Configure: SSG output, React integration, Tailwind
- Migrate Base layout, Nav, Footer
- Extract Three.js Scene3D as React island with `client:idle`
- Homepage renders full HTML statically, Three.js loads lazily

### Session 2: Service pages + blog
- Create Service layout with schema injection
- Migrate all 7 service pages (IT + content from noscript blocks)
- Set up content collections for blog
- Migrate 5 blog posts

### Session 3: Multilingual (EN + BG)
- Create i18n utility functions
- Duplicate pages with localized slugs
- EN: /en/services/web-development/
- BG: /bg/uslugi/web-razrabotka/
- hreflang generation helper

### Session 4: Interactive islands
- Migrate ContactForm as React island
- Migrate AITerminal as React island
- Migrate AdminPanel as React island (client:only — no SSR)
- Migrate /test/ analyzer page

### Session 5: Polish + deploy
- Sitemaps (auto-generated by @astrojs/sitemap)
- Schema.org injection per page type
- OG images per page
- Nginx config update
- Final testing + deploy

## What Stays the Same
- All PHP API endpoints (analyze.php, contact.php, monitor.php, etc.)
- Nginx server configuration (just update root path)
- Domain, SSL, DNS
- All static assets (logo, images, fonts)

## What Changes
- Build output: `dist/` contains fully rendered HTML pages (not SPA)
- No more `<noscript>` blocks — content IS the HTML
- Bundle size drops from 289KB → ~50KB (only interactive islands)
- PageSpeed Performance: 60-80 → 95+

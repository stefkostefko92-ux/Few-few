# СУПТО декларация пред НАП — карта на съответствието (Приложение № 29, Н-18)

Работен документ за подаване на декларацията за съответствие от производителя
„Карбон Стелт“ ЕДПК (ЕИК 208725180). Всяко изискване → къде е реализирано в
Carbon Stealth POS v1.0.0. Провери актуалната редакция на Н-18 преди подаване
(режимът става задължителен с Бюджет 2026, очаквано от ~април 2026).

## Идентификация на софтуера

| Реквизит | Стойност |
|---|---|
| Наименование | Carbon Stealth POS |
| Версия | 1.0.0 (`src/lib/constants.ts` → APP_VERSION; видима на входния екран) |
| Производител | „Карбон Стелт“ ЕДПК, ЕИК 208725180, гр. Бобов дол 2670, ул. „Самуил“ № 3 |
| Тип | локална инсталация (Windows .exe), офлайн-first, SQLite |
| БД достъп | само през приложението; файлът е в потребителския профил на касата |

## Карта на изискванията (Прил. № 29)

| Изискване | Реализация | Къде |
|---|---|---|
| **УНП** — уникален номер на всяка продажба, формат ФУ(8)-оператор(4)-пореден(7) | генерира се при откриване на продажбата; печата се на бона при СУПТО режим | `src/lib/unp.ts`, `api/sales/route.ts` |
| УНП не се дублира/преизползва | атомарен пореден брояч в транзакция (общ за продажби и сторно); `Sale.unp @unique` | `src/lib/counters.ts`, `prisma/schema.prisma` |
| Свързаност с фискалното устройство; бон за всяка продажба | продажба се записва САМО след успешен фискален бон; драйвери за одобрени ФУ (Datecs/Tremol/Daisy/Eltrade/Incotex през ErpNet.FP; Tremol ZFPLab) | `src/lib/fiscal/` |
| Сторно по чл. 31 — 3 причини, срокова контрола, сторно бон | вкл. собствен УНП на сторно бона и препратка към оригинала | `api/sales/[id]/storno/route.ts` |
| Забрана за изтриване/подмяна на данни за продажби | продажби не се трият (само сторно); стоки се деактивират; редовете пазят snapshot на име/цена | схема + API дизайн |
| Одиторска следа на всяко действие | само-добавящ `AuditLog` (вход, продажба, сторно, промени на настройки/потребители/цени) | `src/lib/audit.ts` |
| Оператори с уникален код и роли | код на оператор 1–9999 (в УНП), ПИН (bcrypt), роли касиер/управител/администратор; заключване при 5 грешни опита | `src/lib/auth.ts`, `login-throttle.ts` |
| Експорт на данните за НАП при проверка | CSV експорт в стил Прил. 29 (продажби, УНП, ДДС по групи, сторно) | `api/export/nap` |
| Данъчни групи чл. 27 | А=0%, Б=20%, В=горива, Г=9% — конфигурируеми ставки | `src/lib/constants.ts`, `vat.ts` |
| Дата/час на операциите | всички записи с timestamp; боновете с дата/час от ФУ | схема |
| Идентификация на версията | видима на входния екран + в този документ; нова версия → нова декларация при промени в обхвата | `constants.ts` |

## Задължения на производителя/разпространителя

- **Списък на клиентите** (чл. 52и): магазинът събира имейл + ЕИК на купувача
  (Checkout поле „ЕИК/Булстат“); експорт: `store/scripts/nap-clients-export.mjs`
  → CSV (дата, имейл, ЕИК, план, брой каси, статус).
- **Нова версия** със засягащи промени → актуализация на декларацията.
- Декларацията се подава по електронен път през портала на НАП с **КЕП**.

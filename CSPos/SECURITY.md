# SECURITY.md — Касата

## Модел на заплахите

Касова система в търговски обект: пари в брой, лични данни на служители и
клиенти (лоялни карти), фискално-счетоводни данни. Основни рискове: злоупотреба
от персонал (сторно/липси), кражба на данни, подправяне на записи.

## Мерки

**Автентикация и права**
- Вход с код на оператор + ПИН (bcrypt, cost 10); сесия в подписан JWT
  (HS256, jose) в httpOnly/SameSite=Lax бисквитка, изтичане 14 ч.
- Роли: касиер (продажби) < управител (сторно, склад, отчети, служебни суми)
  < администратор (настройки, потребители). Проверка на всяко API.
- Неуспешните входове се одитират (`LOGIN_FAILED`).

**Цялост на данните (СУПТО принципи)**
- Без DELETE: стоки се деактивират, продажби се сторнират с бон от ФУ.
- Одиторски дневник само-добавящ: кой, кога, какво, с JSON подробности.
- Складова книга (`StockMovement`) за всяка промяна на наличност.
- Сумите се изчисляват само на сървъра; Zod валидация на всеки вход.

**Уеб слой**
- Security headers (X-Frame-Options DENY, nosniff, Referrer-Policy,
  Permissions-Policy); `robots: noindex`; без external скриптове/трекери.
- Продукция: само през HTTPS reverse proxy (Nginx + Let's Encrypt),
  `secure` бисквитки. Системата е за локална мрежа на обекта — не я излагай
  публично без VPN/allowlist.

**Тайни**
- `SESSION_SECRET` и `.env` живеят само на машината (права 600) — никога в
  репото или деплой архива. SumUp API ключът се пази в БД на касата (Setting) —
  тя е локална; при облачно разгръщане премести го в env.

**GDPR (виж docs/COMPLIANCE.md §6)**
- Минимизация: клиентската карта изисква само име; телефонът е по избор.
- Раздел��и основания: транзакции (законово задължение — пази се ≥10 г. по ЗСч)
  срещу лоялна програма (съгласие, изтриваемо след оттегляне).
- ПИН-овете са само хеширани; няма пароли в одиторския дневник.

# CLAUDE.md — CSPos/

Касата — касова (POS) система за хранителни магазини. BG. Евро-готова.

## Стек и команди

Next.js 15 App Router · React 19 · TS strict · Prisma + **SQLite** (offline-first)
· Tailwind · Zod · jose. Path alias `@/*`.

```bash
npm run dev / build / start
npm run lint && npm run typecheck && npm test   # качествена порта (задължителна)
npx prisma db push && npm run db:seed           # локална база + демо данни
```

В пясъчници без директен интернет Prisma engines не се свалят от node fetch —
свали ги с curl от `binaries.prisma.sh/all_commits/<enginesVersion>/debian-openssl-3.0.x/`
в `node_modules/@prisma/engines/` и ползвай `PRISMA_QUERY_ENGINE_LIBRARY` /
`PRISMA_SCHEMA_ENGINE_BINARY` (+ `prisma db push --skip-generate`).

## Твърди правила на домейна (не ги чупи!)

- **Пари = int евроценти. Количества = int хилядни** (`qtyMilli`, 1000 = 1 бр./кг).
  Никакви float в парична аритметика.
- **BGN е само информативен**: `eurCents * 1.95583`, закръгляне half-up
  (`src/lib/money.ts`). Обратно превалутиране — с ДЕЛЕНЕ (чл. 13 ЗВЕРБ).
- **Данъчни групи чл. 27 Н-18: А=0%, Б=20%, В=течни горива (20%), Г=9%.**
  В и Г често се бъркат — при съмнение виж `docs/COMPLIANCE.md`.
- **Продажба без успешен фискален бон не се записва.** Ред: карта → фискален
  бон → транзакция (запис + склад). Отказ на ФУ след карта → опит за refund.
- **Нищо не се трие**: стоки се деактивират, продажби се сторнират (чл. 31 —
  3 причини, срок за операторска грешка до 7-о число на следващия месец),
  одиторският дневник е само-добавящ. СУПТО принципи (Прил. № 29).
- **УНП**: `ФУ(8)-оператор(4)-пореден(7)` — `src/lib/unp.ts`; печата се при
  `fiscal.suptoMode`.
- **Сумите се смятат само на сървъра** — клиентът праща продукти/количества.
- Тегловни баркодове: маски в Settings (`28`=тегло, `29`=цена по подразбиране);
  търсене на артикул САМО по PLU цифрите; EAN контролната цифра се валидира.

## Архитектура

- `src/lib/fiscal/` — драйвери ФУ: `demo`, `erpnet` (мост :8001, препоръчан),
  `tremol` (ZFPLab :4444), `datecs-lan` (експериментален). Интерфейс в `types.ts`;
  нов драйвер се регистрира в `index.ts` + `FISCAL_DRIVERS`.
- `src/lib/terminal/` — ПОС терминали: `demo`, `mypos-ecr` (TCP 7900/60180),
  `sumup` (Cloud API), `borica` (заготовка — спецификация под NDA), `none`.
- `Setting` таблица = key→JSON; типизиран достъп през `src/lib/settings.ts`
  (сливане с подразбиранията).
- Роли CASHIER < MANAGER < ADMIN — `requireRole()` в `src/lib/auth.ts`;
  страниците се пазят от `middleware.ts`, API-тата сами връщат 401/403.
- Складът се движи САМО през `StockMovement` в транзакция с операцията.
- **Промоции** (`src/lib/promotions.ts` чиста логика + `promotions-db.ts` заявка):
  `bestPromotion()` избира най-ниската цена за стока/категория по период+часове+
  количество; сменя ефективната единична цена в продажбата (не при заключена
  цена — свободна продажба/ценови баркод). POS показва промо цена информативно;
  сървърът остойностява официално.
- **Фактури** (`src/lib/invoice-text.ts`): чл. 114 ЗДДС, пореден 10-разряден №
  (Setting `invoiceCounter`), една на продажба (`Invoice.saleId @unique`).
- **Срок на годност**: `/api/expiry` чете партиди от `DeliveryItem.expiryDate`,
  FEFO ред. Разходът НЕ се води по партида — списъкът е „провери рафта“, не
  точен остатък.

# Carbon Stealth POS — касова (POS) система за хранителни магазини

Пълна касова система за български хранителни магазини: продажби с баркод
скенер и тегловни баркодове, фискални устройства, ПОС терминали, склад,
смени, отчети и одиторска следа. **Евро-готова** — работи в EUR с двойно
обозначаване BGN по курс 1.95583 (ЗВЕРБ). Работи на **тъч монитор** и се
доставя като **Windows .exe инсталатор** (виж [`desktop/DESKTOP.md`](desktop/DESKTOP.md)).

Изградена след пазарно и правно проучване (юли 2026) — виж
[`docs/COMPLIANCE.md`](docs/COMPLIANCE.md), [`docs/MARKET.md`](docs/MARKET.md) и
[`docs/CONFORMITY.md`](docs/CONFORMITY.md) (съответствие, устройства, пътна карта).

## Възможности

**Каса (POS екран)**
- Баркод сканиране: EAN-13/EAN-8, **тегловни баркодове 28 IIIII WWWWW C**
  (Microinvest/Еликом конвенция) и ценови баркодове 29… с конфигурируеми маски
- Бързи бутони по категории (цветово кодирани), търсене, кратки PLU номера
- Тегловни стоки с модал за тегло (или направо от етикета на везната)
- Плащане: в брой (с ресто и бързи купюри), с карта през терминал, смесено
- Клиентски карти с отстъпка; двойни цени EUR/BGN на всяка стъпка
- **Задържане/връщане на бонове** (обслужи друг клиент по средата)
- **Отстъпка на целия бон** (%), **свободна продажба** с ръчна цена по ДДС група
- **Вересия** (отложено плащане по клиентска карта) с погасяване и служебен бон
- **Промоции** — промо цена, % отстъпка или **„М за N“ (3 за 2)** за стока/категория,
  за период + happy hour часове + минимално количество; POS прилага най-изгодната
  (промо етикет / „3 ЗА 2“ значка)
- **Проверка на цена** — клиентски терминал „сканирай и виж голяма цена“ (`/check`)
- Анулиран ред/бон се одитира с количество и стойност (СУПТО практика)
- Клавишни комбинации (F9 плащане, F8 карта); светъл liquid-glass тъч интерфейс,
  градиентен акцент на тоталите

**Промоции** (`/promotions`, роля управител)
- Обхват: конкретна стока или цяла категория; тип: % отстъпка или фиксирана промо цена
- Валидност по период (дати) + по избор happy hour (часови диапазон) + минимално количество
- POS показва промо цена + зачертана каталожна; сървърът остойностява официално

**Фактури** (чл. 114 ЗДДС)
- Издаване към приключена продажба с данни на купувача (име/ЕИК/ЗДДС/адрес/МОЛ)
- Последователна 10-разрядна номерация без пропуски; данъчна основа + ДДС + общо
- Двувалутно EUR/BGN; печатен изглед; една фактура на продажба

**Срок на годност (FEFO)**
- Партиди от доставките (стока, партида, срок), подредени по изтичане
- Аларма на таблото (7 дни) и таб в склада; бърз брак на изтекли партиди

**Фискализация (Наредба Н-18)**
- Продажба се приключва САМО с фискален бон; без бон — без запис
- Данъчни групи по чл. 27: **А=0%, Б=20%, В=горива, Г=9%** (конфигурируеми ставки)
- **Сторно** по чл. 31 с трите причини + срокова контрола (7-о число за
  операторска грешка) + сторно бон от ФУ
- **УНП** по Приложение № 29: `ФУ(8)-оператор(4)-пореден(7)` (СУПТО режим —
  доброволен, превключва се от Настройки)
- Служебно въведени/изведени суми със служебни бонове; X/Z отчети
- Двойно обозначаване на крайната сума (EUR + BGN + курс) до 08.08.2026

**Драйвери за фискални устройства** (`src/lib/fiscal/`)
- **ErpNet.FP мост** (препоръчан) — един JSON API за Datecs, Tremol, Daisy,
  Eltrade, Incotex по COM/Bluetooth/LAN (`localhost:8001`, лиценз 0BSD)
- **Tremol ZFPLab** — официалният HTTP сървър на Tremol (`localhost:4444`)
- **Datecs X по LAN** — директен wire протокол (експериментален)
- **Демо** — пълна симулация с текстови бонове за разработка/обучение

**ПОС терминали** (`src/lib/terminal/`)
- **myPOS ECR** по LAN (порт 7900 Android / 60180 K300)
- **SumUp Solo** през Cloud API
- **BORICA** — адаптер-заготовка (спецификацията е под NDA от office@borica.bg)
- **Демо** — симулация; и режим „без връзка“ за самостоятелен терминал
- Карта се таксува ПРЕДИ фискалния бон; при отказ на ФУ — автоматичен опит
  за връщане по картата

**Склад**
- Доставки със заприхождаване, партида и срок на годност (Регламент 178/2002)
- Ревизии с изравняване (липси/излишъци), брак с причина
- Единна складова книга (`StockMovement`) — всяка промяна е проследима
- Праг „изчерпва се“ с аларма на таблото

**Смени и пари**
- Отваряне с начална наличност, закриване с преброяване + Z-отчет
- Очаквана наличност срещу преброена (разликата се одитира — чл. 207 КТ)
- Служебно въвеждане/извеждане с основание

**Отчети и одит**
- Оборот по дни/касиери/стоки, ДДС по групи (нето след сторно)
- **CSV експорт за НАП одит** (стил Приложение № 29)
- Несменяем одиторски дневник: всяко действие, по оператор
- Без изтриване на данни — стоките се деактивират, продажбите се сторнират

**Администриране** (`/settings`, роля администратор)
- **Данни на фирмата** — наименование, ЕИК, ЗДДС №, МОЛ, обект, адрес, телефон,
  текст на дъното на бона; печатат се на всеки фискален бон (чл. 26 Н-18) и
  фактура (чл. 114 ЗДДС)
- Бутони **„Преглед на бон“** и **„Преглед на фактура“** — показват как изглежда
  документът с текущите данни, преди запис
- Фискално устройство и ПОС терминал (драйвер, адрес, УНП реквизити, СУПТО режим)
- Двойно обозначаване EUR/BGN, ДДС ставки по групи, маски за тегловни баркодове,
  управление на потребители и роли

**Роли**: Администратор → Управител → Касиер (вход с код на оператор + ПИН)

## Стек

Next.js 15 · React 19 · TypeScript (strict) · Prisma · **SQLite** (offline-first —
касата работи без интернет) · Tailwind CSS · Zod · jose · bcryptjs

## Пускане

```bash
cd CSPos
npm install
cp .env.example .env        # попълни SESSION_SECRET (openssl rand -hex 32)
npx prisma db push          # създава cspos.db
npm run db:seed             # демо данни: 50 стоки, 3-ма потребители
npm run dev                 # http://localhost:3000
```

Демо ПИН кодове (смени ги!): администратор **1/9999**, управител **2/5555**,
касиер **3/1111**. Демо клиентска карта: **1000001** (3%). Тегловен баркод за
проба: **2800203004502** (PLU 203 — сирене, 0,450 кг).

## Качествена порта

```bash
npm run lint && npm run typecheck && npm test && npm run build
```

## Свързване на истинско фискално устройство

1. Инсталирай [ErpNet.FP](https://github.com/erpnet/ErpNet.FP) на касовия
   компютър (Windows/Linux/RPi) — открива устройството автоматично.
2. Настройки → Фискално устройство → драйвер „ErpNet.FP мост“, адрес
   `127.0.0.1`, порт `8001`, Printer ID от админ панела на моста.
3. Въведи индивидуалния № на ФУ (за УНП) и № на фискалната памет.
4. Провери статуса (зелената точка „ФУ“ в заглавната лента).

Пълни технически бележки за устройства, терминали и везни:
[`docs/INTEGRATIONS.md`](docs/INTEGRATIONS.md).

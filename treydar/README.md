# Трейдъра (`treydar/`) — spot трейдинг бот за Binance

Автоматизиран **spot** трейдинг бот с **риск-мениджмънт като първо правило**. Създаден и
поддържан от агента **Трейдъра** (`.claude/agents/treydara.md`).

> ⚠️ **ВАЖНО — прочети преди да пуснеш каквото и да е.**
> Това е **софтуерен инженеринг, не инвестиционен/финансов съвет**. Автоматизираната търговия
> носи риск от **загуба на целия капитал**. Никой бот не гарантира печалба. Примерната стратегия
> (SMA crossover) е **placeholder за демонстрация**, не печеливша система. Тествай на **testnet** и
> направи **бектест**, преди да рискуваш реални пари. Използвай само средства, които можеш да
> загубиш. При търговия с чужди пари или предоставяне на „съвет“ важат лицензионни изисквания
> (в ЕС: MiFID II) — консултирай юрист.

## Какво прави (и какво НЕ прави)

**Прави:** следи един пазар (напр. `BTC/USDT`), на затворени свещи смята сигнал, при вход изчислява
размер **от риска** (не от „колко искам да вложа“), слага **stop-loss на борсата** веднага след
покупка, и спазва дневен лимит на загубата + глобален **max-drawdown kill-switch**.

**НЕ прави:** не тегли пари (не му трябват withdrawal права), не използва лост (spot), не обещава
печалба, не търгува с реални пари без изричното ти потвърждение.

## Инсталация

```bash
cd treydar
npm install
cp .env.example .env      # попълни ключове и параметри
```

## Безопасност на API ключа (задължително)

1. В Binance създай API ключ **само с „Enable Spot Trading“ + четене**.
2. **Изключи „Enable Withdrawals“.** Ботът никога не тегли.
3. Включи **IP allowlist** (restrict access) към IP-то на машината.
4. Ключовете стоят в `.env` (в `.gitignore`) — **никога** в git.

## Режими (трипосочна спирачка срещу случайна загуба)

Реални пари се движат само при **изричен** избор. Йерархия:

| `BINANCE_TESTNET` | `TRADING_LIVE` | `I_UNDERSTAND_THE_RISK` | Режим |
| --- | --- | --- | --- |
| `true` (default) | `false` (default) | — | 🟢 **DRY-RUN** — само логва намерения |
| `true` | `true` | — | 🟡 **Testnet live** — реални поръчки, фалшиви пари |
| `false` | `true` | `РАЗБИРАМ-РИСКА` | 🔴 **РЕАЛНИ ПАРИ** |

Ако поискаш реални пари без `I_UNDERSTAND_THE_RISK=РАЗБИРАМ-РИСКА`, ботът **отказва да стартира**.
Това е нарочно.

## Препоръчан път (не прескачай стъпки)

```bash
# 1) Бектест (публични данни, без ключове). Гледай walk-forward: бие ли B&H устойчиво през фолдовете?
npm run backtest                 # или: node src/backtest.js ETH/USDT 4h

# 2) Тестове на риск логиката
npm test

# 3) Dry-run срещу реални цени, но БЕЗ поръчки
npm run dry

# 4) Testnet live (ключове от https://testnet.binance.vision, BINANCE_TESTNET=true, TRADING_LIVE=true)
npm start

# 5) Чак след като си доволен: реален Binance с малка сума и всичките три флага.
```

## Стратегии

По подразбиране **`STRATEGY=trend`**: влиза само по посока на дългия тренд (цена над `EMA_TREND`),
на `EMA_FAST`/`EMA_SLOW` cross нагоре, ако не е прегрят (`RSI < RSI_OVERBOUGHT`); стопът е **ATR-базиран**
(`вход − ATR × ATR_MULT`) — адаптира се към волатилността, вместо фиксиран %. `USE_TRAILING=true`
качва стопа нагоре при движение в твоя полза. Има и прост `STRATEGY=sma` (crossover) за сравнение.

⚠ Нито една от тях не е гаранция за печалба. Смисълът на бектеста е да покаже дали изобщо си струва.

## Как да четеш бектеста (`npm run backtest`)

- **Walk-forward фолдове** — 4 последователни out-of-sample прозореца. Търсиш **устойчивост**:
  печели ли в повечето фолда, или само в един (късмет)? Ред `бие B&H в X/4 фолда` е ключов.
- **Buy & Hold (B&H)** — ако не биеш простото държане устойчиво, стратегията **не струва** за реални
  пари. `✅/❌` до всеки фолд показва това.
- **Метрики** — Sharpe/Sortino (доходност спрямо риск), max DD (най-лошото пропадане), profit factor
  (>1.5 е прилично), win% и expectancy, exposure (колко време си в пазара).
- **Robustness grid** — вариране на `atrMult × emaFast`. **Тесен и положителен разлив** = устойчиво;
  голям разлив min→max = крехко/overfit (не вярвай на един „щастлив“ набор параметри).

## Как да замениш/донастроиш стратегията

Пипаш `src/strategy.js`: `signalAt(ctx, i)` връща `'long' | 'exit' | null` за **затворената** свещ `i`;
`stopDistance(ctx, i, entry)` дава разстоянието до стопа. Дисциплина: никакво четене на бъдещи барове
(има тест за това); сигналът се изпълнява на отваряне на следващия бар. След всяка промяна →
`npm run backtest` и гледай walk-forward + robustness, преди testnet/live.

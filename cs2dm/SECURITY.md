# SECURITY.md — cs2dm

## Модел на заплахите (фаза 1)

Ванилов CS2 сървър на **споделения VPS** заедно с другите продукти (вкл. medqr със здравни данни).
Без плъгини, без база, без уеб панел, без RCON. Основните рискове:

| Риск | Мярка |
|---|---|
| Пробив в процеса на играта → достъп до другите продукти | отделен системен потребител `cs2` без shell; systemd: `ProtectSystem=strict` (запис само в `/opt/cs2`), `ProtectHome`, `PrivateTmp`, `NoNewPrivileges`, `ProtectKernel*`, `RestrictSUIDSGID` |
| `cs2` подменя скрипт, който root изпълнява | скриптовете на root са в `/usr/local/lib/cs2dm` (root:root), не в дома на `cs2` |
| Изтичане на GSLT | само в `/etc/cs2/cs2.env` (root, 0600); никога в репото, cfg или логове. ⚠️ Подаден е на сървъра като аргумент `+sv_setsteamaccount` (стандартният начин) → вижда се в `/proc/<pid>/cmdline` за локални потребители; на машината няма външни потребители |
| Бан на GSLT (перманентен) | нула плъгини за предмети/рангове; служебен Steam акаунт със собствен телефон |
| RCON brute-force (в CS2 няма защита — `sv_rcon_*failures` са developmentonly) | фаза 1 е **без** `-usercon`; TCP 27015 затворен навън |
| DDoS по IP-то на играта сваля и сайтовете | вградените A2S лимити; изходен план към отделна машина/IP |
| Изтощаване на CPU/RAM за сайтовете | `CPUWeight`/`Nice` за играта, `sv_hibernate_when_empty 1`; наблюдение |
| Подменен SteamCMD/игра | сваляне само по HTTPS от официалния CDN на Valve; `--validate` при съмнение |

## Фаза 2 — модове (native код в процеса на играта)

| Риск | Мярка |
|---|---|
| Подменен архив на мод (supply chain) | всеки архив е заключен по sha256 в `mods.lock`; несъвпадение → нищо не се инсталира |
| Мод с достъп до предмети/рангове → GSLT бан | `FollowCS2ServerGuidelines: true` в `core.json`; тест забранява `false`; нула скин плъгини |
| Ъпдейт на CS2 чупи модовете → сървърът лежи | автоматичен ванилов старт + нов опит на 6 часа |
| Gamedata на CSS идва по **HTTP** (`http://gamedata.cssharp.dev`) | ⚠️ CSS е компилиран без TLS в httplib — HTTPS не работи; gamedata са данни (сигнатури), не код; MITM по пътя VPS → cssharp.dev би могъл най-много да срине сървъра → systemd го вдига, резервът важи |
| Админ права в играта | само собственикът (`CS2_OWNER_STEAMID64` → `@css/root`) до нашата админ система на Postgres |

## Фаза 3 — плъгинът CarbonStealth

| Риск | Мярка |
|---|---|
| Тайни (база, Redis, ключ на моста) в процеса на играта | конфигът е `0600`, собственик `cs2`, пише го `install-plugins.sh` от `/etc/cs2/cs2.env`; никога в репото/лога |
| Подправена команда от Redis (kick/ban от „сайта“) | HMAC-SHA256 подпис върху суровия payload, сравнение с постоянно време, ±30 s, replay guard (1000 id); ключ < 32 знака → мостът е изключен |
| Цветови/конзолни инжекции през ник или чат | `Text.SafeName`/`SafeText` махат контролни знаци и `{}`; `kickid` текстът е без `"` и `;` |
| SQL инжекция | само параметризирани заявки (Npgsql); наказание + одит в една транзакция |
| Злоупотреба на модератор | 7 роли с immunity (действие само срещу по-ниска роля), бан над 7 дни — само ADMIN+, всичко в одит-веригата |
| Банер-модел с чужд път / `..` в манифеста | ключ `a-z0-9_-`, път само `models/….vmdl` — проверка и в `plugin-config.mjs`, и в плъгина |
| Подменен NuGet пакет / SDK | `RestoreLockedMode` (версия + хеш от `packages.lock.json`), SDK контейнерът е закован по digest, DeathmatchAPI.dll идва от архива с sha256 от `mods.lock` |
| Банерите спират куршуми | моделите са без physics, `prop_dynamic_override` със `SOLID_NONE` |

## Сайтът (`app/`, cs2.carbonstealth.eu) — етап 1, само публичната част

Express 5 зад nginx на хоста; Postgres, Redis, сайт и работник в Docker Compose на същия VPS.

| Риск | Мярка |
|---|---|
| Изтичане на вътрешната причина за бан, IP или админ | публичният банлист чете само `PUBLIC_BAN_SELECT` (5 полета); типът `PublicBan` няма `reason`; маршрутът изброява полетата пак; тест с „течащ“ ред |
| Публичен профил въпреки възражение (чл. 21 GDPR) | `hidden_from_leaderboards` → 404 на профила, извън класацията и sitemap |
| Heatmap като радар за читъри | само агрегати по клетки 32 px, 30 дни със закъснение 1 час; никога позиции на живо |
| Фалшив статус „онлайн“ | `cs2dm:live` се проверява със zod и по възраст; иначе „неизвестен“, без `serverStatus` |
| XSS през ник/име на оръжие (идват от играта) | EJS екранира; контролни/bidi знаци се махат; JSON-LD екранира `<`, `>`, `&`; SVG-ът екранира title/desc; строг CSP (`script-src 'self' 'nonce-…'`, `style-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'none'`) |
| Невалиден вход (SteamID, сезон, страница) | zod на всеки параметър; SteamID64 `^7656119\d{10}$`, иначе 404 без заявка към базата |
| SQL инжекция | Prisma с параметри; подредбата на класацията е от затворен списък, никога от вход |
| Претоварване/скрейпинг | express-rate-limit 120/мин на IP (в паметта, 1 мин); кратък кеш пред базата; само GET/HEAD |
| Аватар от чужд хост | само `https://avatars.*.steamstatic.com`, `referrerpolicy="no-referrer"`, в CSP `img-src` |
| Достъп до базата/Redis отвън | портовете са вързани САМО за `127.0.0.1` (5442/6392/4350); Redis с `requirepass`; healthcheck-ът се автентикира през `REDISCLI_AUTH` |
| Пробив в контейнер | read-only файлова система, `cap_drop: ALL` (Postgres — само нужните), `no-new-privileges`, лимити на памет/CPU/процеси, непривилегирован `node`, образи заковани по digest (node, postgres) |
| Тайни | само в `cs2dm/app/.env` на сървъра (0600): `POSTGRES_PASSWORD`, `REDIS_PASSWORD`; `.env.example` е с празни стойности |
| Логове с лични данни | pino без IP и без query низа, позитивен списък на заглавията; nginx без access log |

⚠️ Не е направено на етап 1: отделна роля в Postgres за C# плъгина с минимални права (сега и
плъгинът, и сайтът са `cs2dm`); `redis:7-alpine` не е заковано по digest (няма демон за
`imagetools inspect` в средата, където е писан). Входът със Steam и панелът — етап 2 (по-долу); формата за
обжалвания и VIP заявките от играчите — следващ етап.

## Агентът на сървъра (`cs2-agent`, CONTRACT §9)

Сайтът (Docker) управлява играта само през малък агент на хоста, който приема подписани команди от
Redis: `status`, `restart`, `update`, `logs`. Нищо друго.

| Риск | Мярка |
|---|---|
| Пробит сайт/контейнер → root на хоста | **агентът не е root**: системен потребител `cs2agent` без shell; `CapabilityBoundingSet=` (празно), `NoNewPrivileges`, `ProtectSystem=strict` без `ReadWritePaths` (не пише никъде), `ProtectHome`, `PrivateTmp`, `PrivateDevices`, `ProtectProc=invisible`, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6`, `SystemCallFilter=@system-service ~@privileged` |
| Агентът кара systemd да прави друго | polkit правило `50-cs2dm-agent.rules`: `cs2agent` може **само** `restart` на `cs2.service` и `start` на `cs2-update.service` (детайлите `unit`/`verb` на systemd); всяко друго действие от `cs2agent` — изричен `NO` (никое следващо правило не може да го разреши). Инсталаторът го проверява с `pkcheck` и спира агента, ако polkit разрешава повече |
| Подправена команда в Redis (всеки с достъп до Redis) | HMAC-SHA256 с **отделен** ключ `CS2DM_AGENT_KEY` (изтекъл ключ на моста към плъгина не дава systemd), сравнение с постоянно време, ±30 s, replay guard (1000 id); payload-ът се парсва след подписа; отхвърлената команда няма отговор |
| Инжекция на команди | `execFile` без shell, само `/usr/bin/systemctl` и `/usr/bin/journalctl` (allowlist в кода и тест); аргументите са константи; единственият вход е `lines` (цяло 1…200) и `source` (`css`/`journal`) |
| Тайни и лични данни в логовете към панела | всеки ред минава през редакция: IPv4/IPv6 → `x.x.x.x`, `sv_setsteamaccount <…>`, `logon token …`, всеки 32+ hex низ (ключове, пароли от `openssl rand -hex`) и `password=…` → `<redacted>`; ANSI/контролни знаци вън; таван на реда. Над-редакцията е приета |
| GSLT от `/proc/<pid>/cmdline` на играта | `ProtectProc=invisible` — агентът не вижда чужди процеси; конфигът на плъгина (с паролите) и SteamCMD — `InaccessiblePaths` |
| Изтичане на ключовете | `/etc/cs2/agent.env` 0600 root — чете го systemd преди смяната на потребителя; ключът не е в командния ред; агентът го маха от средата си, децата получават минимална среда; инсталаторът не печата тайни и подава стойностите на `awk` през средата (не през argv) |
| Рестарт-цикъл от панела | `restart`/`update` са еднопоточни (`busy`), `busy` и докато тече `cs2-update.service`; правата и одитът — в сайта (§10) |
| Подменен код на агента | `/usr/local/lib/cs2dm/agent` е root:root 0644 — `cs2agent` и `cs2` не могат да го пипат |
| Агентът пада или зацикля | `Restart=always` + `StartLimit*`, `MemoryMax=256M`, `TasksMax=64`, `Nice=5` (играта е с приоритет) |

`logs` връща редове с ник и SteamID (лични данни) — само към панела (роля ≥ `HELPER`, §10); агентът не ги
пази. ⚠️ polkit и systemd **не са проверени** в средата, където агентът е писан (контейнер без systemd като
PID 1) — проверява ги `install-agent.sh` на машината (`pkcheck` за разрешеното и забраненото + подписан
`status`/`logs`). На polkit < 121 (Ubuntu 22.04) инсталаторът отказва.

## Уеб панелът (`/admin`, CONTRACT §10) — етап 2

Пълен админски достъп от сайта: наказания, роли, VIP, доклади, обжалвания, банери, одит, сървърът.
Кодът е `app/src/admin/`; всяко писане минава: сесия → TOTP → право по §1 → immunity → CSRF → запис +
одит в една транзакция → (ако трябва) подписана команда.

| Риск | Мярка |
|---|---|
| Фалшив вход („аз съм админът“) | само Steam OpenID 2.0; отговорът се приема след `check_authentication` (POST към steamcommunity.com, адресът е твърд), `return_to` трябва да е ТОЧНО нашият с еднократен nonce от бисквитката `__Host-cs2dm_oid` (връзва отговора с браузъра, започнал входа), подписани `op_endpoint/claimed_id/identity/return_to/response_nonce/assoc_handle`, nonce не по-стар от 5 мин; `claimed_id` → `^7656119\d{10}$` |
| Достъп на играч | сесия се създава само при `players.role ≥ HELPER`; иначе 403 без бисквитка |
| Откраднат Steam акаунт на админ | TOTP е **задължителен** (RFC 6238, ±1 стъпка, повторен код се отхвърля — `players.totp_last_step` се вдига атомарно); без включен TOTP се вижда само записването; 5 грешни кода → сесията пада; резервните кодове са еднократни |
| Изтичане на базата | токенът на сесията — само sha256; TOTP тайната — AES-256-GCM с ключ, изведен (HKDF) от `APP_ENC_KEY`, AAD = SteamID; резервните кодове — само HMAC с отделен изведен ключ |
| Кражба/фиксиране на сесия | `__Host-cs2dm_sid`: HttpOnly, Secure, SameSite=Lax, Path=/ без Domain; 12 ч от входа (10 мин до TOTP); нов токен и нов CSRF след TOTP; ролята при входа е в сесията — смяна на `players.role` (панел, игра, бот) прекратява всички сесии; „изход навсякъде“ |
| CSRF | synchronizer token на всяка POST форма (вързан със сесията, сравнение с постоянно време) + проверка на `Origin`/`Referer` спрямо `PUBLIC_BASE_URL`; GET никога не пише |
| Повишаване на права | всеки маршрут декларира възможност в типа си (тест обхожда таблицата); действие върху цел — immunity (само по-ниско ниво; OWNER не се пипа, и не върху себе си); роли — само под своята, без VIP/OWNER; проверката е ПРЕДИ записа и ПРЕДИ подписа |
| Подправена команда към плъгина/агента | плик `{p, sig}`, HMAC-SHA256 върху UTF-8 байтовете на `p` (векторът е общ с C#), отделни ключове `CS2DM_BRIDGE_KEY` и `CS2DM_AGENT_KEY` (≥ 32 знака); отговорът се чака по `id` с наш таймаут (отказаната команда няма отговор) |
| Липсващ ключ | fail closed: без `APP_ENC_KEY` панелът е 503, без ключ на моста/агента — съответните команди са отказани; публичният сайт работи; невалиден ключ → само името му в лога |
| Изтичане на причината/IP | вътрешният списък с причина и админ е само в панела; IP на сесиите — само ADMIN+; логовете от агента се редактират и в панела (IP, GSLT, 32+ hex) |
| Brute force | лимити по IP: вход 20/15 мин, TOTP 10/15 мин, POST 60/мин (+ общите 120/мин на сайта) |
| Индексиране/кеш | `noindex, nofollow` (мета + `X-Robots-Tag`), `Cache-Control: no-store`, извън sitemap/llms.txt |
| XSS в панела | EJS екранира; никнеймите минават през `displayName`; строгият CSP с nonce остава (нула inline скрипт/стил; `public/admin.js` само потвърждава формите) |
| Отказ от отговорност | всяко писане → `audit_log` със `source = WEB` в същата транзакция; веригата се проверява от панела със същия израз като тригера |
| Подправени статистики / класация | редакцията е само HEADADMIN+ и само над целта (immunity — и не върху себе си); цели числа ≥ 0 с тавани и проверки (HS/баунти/отмъщения ≤ убийства); всяка промяна → `stats.*` одит с before/after; нулирането иска отметнато потвърждение; епохата (§3) пази редакцията от стари партиди на плъгина |
| „Всичко, което пазим“ — изтичане | само HEADADMIN+; TOTP тайната е само „има/няма“, токените на сесиите, CSRF и хешовете на кодовете не се четат; IP и данни за фактура — както в другите изгледи на екипа (`no-store`, `noindex`) |
| Живите настройки (§11) като вектор | само HEADADMIN+ в панела; строга zod схема на група (затворен списък от ключове, диапазони); собствените реклами се чистят като чата (контролни знаци и `{…}` цветови тагове вън) и в панела, и наново в плъгина; повреден ред в базата → групата пада към конфига на плъгина (никога срив); всяка промяна → `settings.change` с before/after (и от играта) |

⚠️ Не е проверено: истински вход със Steam (тестовете ползват двойник на `check_authentication`), истинският
C# плъгин и истинският агент по Redis (двойници, които проверяват подписа като тях). `WARN` от панела не
стига до чата в реално време — `punish` на плъгина зарежда само активни наказания, а предупреждението е със
срок „сега“ (както в играта). Политиката за поверителност още не споменава бисквитките на панела (строго
необходими, само за екипа).

## Лични данни (GDPR)

Сървърът пише в Postgres: SteamID64, ник, IP при влизане (`sessions`, 30 дни), статистики, убийства с
координати (`kills`, 90 дни), наказания. Сроковете ги прилага работникът (BullMQ, на 6 часа, на партиди)
— обжалванията и докладите се трият 1 година след решение. Политиката за поверителност е на сайта
(`/{bg,en,it}/privacy`, чернова — не правен съвет; хостинг държавата и срокът по ЗСч са за потвърждение).
Чатът от играта **не** се пази в базата (само кратък Redis поток за панела).
Срокът на journald на машината да се ограничи (стандартният лог на играта съдържа ник, SteamID и IP).

## Тайни

Никога в репото или архива. Само на сървъра: `/etc/cs2/cs2.env`, `/etc/cs2/app.env`, `/etc/cs2/agent.env`
(0600 root). Ключовете на панела (`APP_ENC_KEY`, `CS2DM_BRIDGE_KEY`, `CS2DM_AGENT_KEY`) влизат само в уеб
контейнера; `APP_ENC_KEY` не се сменя след първото включване на TOTP (тайните са шифрирани с него). Гейтът
`tools/security/secret-scan.mjs` + тестът „cfg не носи тайни“.

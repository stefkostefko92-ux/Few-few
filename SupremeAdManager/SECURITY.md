## Тайни и токени

- OAuth refresh token (Google) и System User token (Meta) се пазят **само криптирани**
  в SQLite: AES-256-GCM, 12-байтов IV, ключ `ENCRYPTION_KEY` (32 байта hex) от средата.
- `.env` живее на сървъра (mode 600), никога в репото/архива. `ENCRYPTION_KEY` е
  задължителен в продукция (кодът отказва да тръгне без него).
- Токени никога не влизат в логове, одитна следа или страници за грешки.
- Meta: препоръчани 60-дневни System User токени (не „never expires“), scoped към
  минималните активи (един ad account + една page).
- Google: OAuth клиент с минимален scope (`adwords`); ключове без достъп до billing промени.

## Приложна сигурност

- Helmet + строг CSP (`default-src 'self'`, без inline скриптове), `x-powered-by` изключен.
- Сесия: HMAC-подписана httpOnly бисквитка, `SameSite=Lax`, `Secure` в продукция, 8ч живот.
  **Fail-fast**: продукция отказва да тръгне без `SESSION_SECRET` (≥32 знака) — симетрично
  на `ENCRYPTION_KEY`.
- CSRF: double-submit токен на всяка мутация (тестван: POST без токен → 403).
- Rate limit: 600 заявки/15 мин на IP + **отделен строг лимит на входа** (10 неуспешни/15 мин).
- Вход: bcrypt (cost 12) хеш от средата; един админ (собственикът); dev fallback работи
  само извън продукция. Подправена сесийна бисквитка е тествана, че не минава.
- SQLite: prepared statements навсякъде (better-sqlite3), нула конкатенация на SQL.
- Meta токенът върви в `Authorization: Bearer` header, никога в URL (URL-ите текат в
  proxy/APM логове).

## Финансова безопасност (уникално за този продукт)

- Публикуване ВИНАГИ `PAUSED`; активиране само с човешко действие през UI. **Авто-действие
  „activate“ не съществува** в двигателя на правилата (и route-ът отхвърля такова правило).
- Твърди тавани: `GUARD_MAX_DAILY_BUDGET` (на кампания) + `GUARD_MAX_TOTAL_DAILY_BUDGET`
  (общ) — проверяват се при създаване, при активиране И при авто-скалиране
  (`checkBudgetChange` пази и общия таван — тествано).
- Авто-правилата: мин. разход преди действие, cooldown, ±20% таван на бюджетна стъпка.
- „Дневен спирачен праг“ правило: разход днес > 1.5× бюджета → автоматична пауза
  (платформите могат да превишат дневния бюджет до ~2×); pacing аларма при +15%.
- Статусът каскадира по цялата Meta йерархия (campaign → adsets → ads) — пауза значи пауза.
- Пълна одитна следа на всяко действие (кой/кога/какво/dry-run), вкл. consent декларацията
  на оператора (GDPR чл. 7(1) отчетност).

## Съхранение на данни (GDPR чл. 5(1)(д))

- Одитна следа: **24 месеца**, метрики: **25 месеца** — по-старото се изтрива автоматично
  на всеки цикъл на планировчика (`retentionCleanup`).
- Продуктът е **first-party** (собствени рекламни акаунти). Обслужване на клиенти изисква
  първо: DPA (чл. 28), tenant изолация, списък под-обработващи, per-tenant изтриване —
  не е имплементирано и не се предлага.

## Съответствие (ЕС)

- **GDPR/ePrivacy**: EEA кампании изискват потвърден consent слой (Consent Mode v2 / CMP);
  server-side събития НЕ заобикалят съгласието. Custom Audiences изискват декларирано
  правно основание. Хеширане ≠ анонимизация.
- **DSA**: без профилиране под 18; без таргетиране по специални категории (чл. 9 GDPR);
  `dsa_payor`/`dsa_beneficiary` задължителни за Meta ЕС кампании.
- **AI Act чл. 50** (от 02.08.2026): AI-генерирани креативи изискват разкриване +
  машинно-четима маркировка — guard-ът блокира публикуване без потвърждение.
- Политическа реклама не се поддържа изобщо.

## Проверени поуки (verified)
- **2026-06-26:** hreflang return-tag правилото: ако страница X сочи Y, Y трябва да сочи обратно X; ако не е реципрочно за всички, анотациите се игнорират или интерпретират грешно; всяка версия включва и себе си _(hreflang return-tags; verified; https://developers.google.com/search/docs/specialty/international/localized-versions)_
- **2026-06-26:** INP presentation delay се свива с малък DOM и content-visibility за off-screen елементи; processing duration се свива с yield към main thread и batch на DOM reads/writes (избягване на layout thrashing) _(INP оптимизация по фаза; verified; https://web.dev/articles/optimize-inp)_
- **2026-06-26:** Mobile-first: само съдържанието на мобилната версия се индексира; съдържание зад user interaction (click/swipe/type) НЕ се зарежда и НЕ се индексира; structured data + alt текст + заглавия трябва идентични между mobile и desktop _(mobile-first нюанси; verified; https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)_
- **2026-06-26:** LCP отчита render time на най-голямия елемент в viewport спрямо навигацията; браузърът спира да праща нови entries при първа интеракция (tap/scroll/keypress) — отчитай само последния PerformanceEntry _(LCP измерване; verified; https://web.dev/articles/lcp)_
- **2026-06-26:** Google ВЕЧЕ НЕ ползва rel=next/rel=prev за индексиране; страница 2+ трябва self-canonical, НЕ canonical към страница 1; свързвай с обикновени a href, избягвай # за номер на страница _(pagination; verified; https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)_
- **2026-06-26:** Google използва 75-ти персентил за CWV прагове като компромис: покрива 3 от 4 page views и е устойчив на outliers (на p95 стигат 5 outlier-а от 100 за изкривяване, на p75 трябват 25) _(CWV методика p75; verified; https://web.dev/articles/defining-core-web-vitals-thresholds)_
- **2026-06-26:** При hreflang всяка локализирана версия трябва self-referencing canonical в същия език; канонизиране на един език към друг при едновременен hreflang е забраненият конфликт различни URL като canonical с различни техники _(hreflang canonical конфликт; verified; https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)_
- **2026-06-26:** Soft 404 = HTTP 200 но съдържанието индикира не съществува (празна/тънка страница); хаби crawl budget; фикс: връщай реален 404 (изчезнала) или 410 (премахната завинаги) _(soft 404 статус; verified; https://developers.google.com/search/docs/crawling-indexing/http-network-errors)_
- **2026-06-26:** В SPA клиентски обработена грешка често връща HTTP 200 вместо 404 → soft 404 и нежелана индексация; Google детектира по съдържание, не само по статус; фикс: redirect към реален 404 или noindex meta _(soft 404 в SPA; verified; https://developers.google.com/search/docs/crawling-indexing/javascript/fix-search-javascript)_
- **2026-06-26:** Googlebot обработва JS на 3 фази (crawl→render→index); всички 200-страници влизат в render queue независимо от JS и могат да чакат секунди или повече, затова критичното съдържание трябва в server-HTML _(JS рендиране two-wave; verified; https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)_
- **2026-06-26:** LCP се разлага на 4 фази с целеви дял: TTFB ~40%, resource load delay под 10%, resource load duration ~40%, element render delay под 10%; двете delay фази са чистата възможност за оптимизация _(Core Web Vitals LCP под-фази; verified; https://web.dev/articles/optimize-lcp)_
- **2026-06-26:** INP се разбива на input delay (вход→старт на callback), processing duration (изпълнение на event callbacks в кадъра) и presentation delay (край на callbacks→рендиран следващ кадър); всяка фаза се дебъгва и оптимизира отделно _(Core Web Vitals INP под-фази; verified; https://web.dev/articles/optimize-inp)_
- **2026-06-26:** Всяко robots правило (noindex, nofollow и др.) може да се подаде и през HTTP header X-Robots-Tag вместо meta таг — задължително за не-HTML ресурси (PDF, изображения, видео), където meta таг не е възможен; имената/стойностите са case-insensitive _(X-Robots-Tag HTTP header за не-HTML; verified; https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)_
- **2026-06-26:** Google ползва sitemap <lastmod> само ако е консистентно и проверимо точен (сравнява с реалната последна модификация на страницата); смислена промяна = основно съдържание/структурирани данни/връзки (не смяна на copyright дата); формат ISO 8601; <priority> и <changefreq> се игнорират напълно _(sitemap lastmod точност; verified; https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)_

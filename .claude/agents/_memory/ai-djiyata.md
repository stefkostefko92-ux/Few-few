## Проверени поуки (verified)
- **2026-07-15:** Anthropic Messages API: header `x-api-key` + задължителен `anthropic-version` (напр. 2023-06-01); `system` е ТОП-level параметър, не съобщение с role:system; `max_tokens` е ЗАДЪЛЖИТЕЛЕН. Ключ `sk-ant-…`. Отговорът има `stop_reason` (end_turn/max_tokens/tool_use/stop_sequence) — при `max_tokens` изходът е отрязан, вдигни лимита. _(Anthropic Claude API основи; verified; https://docs.anthropic.com/en/api/messages)_
- **2026-07-15:** Anthropic prompt caching (`cache_control:{type:'ephemeral'}` на breakpoint в system/tools/дълъг контекст): кешираните входни токени са ~10% от цената и по-бързи; TTL 5 мин (или 1 час). Огромен лост за RAG/дълъг system — слагай стабилния контекст ОТПРЕД и кеширай, променливото — отзад. _(cost/latency — prompt caching; verified; https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching)_
- **2026-07-15:** Структуриран изход при Claude = чрез tool use: дефинирай tool с `input_schema` (JSON Schema); моделът връща `tool_use` блок с валиден по схемата вход; ти връщаш `tool_result`. За гарантиран JSON — единствен tool + `tool_choice` да го форсира. Винаги ВАЛИДИРАЙ (Zod) след парсване. _(structured output / tool use (Claude); verified; https://docs.anthropic.com/en/docs/build-with-claude/tool-use)_
- **2026-07-15:** Extended thinking (Claude): параметър `thinking:{type:'enabled',budget_tokens:N}`; reasoning токените се таксуват и ядат от бюджета → `max_tokens` трябва да е > budget_tokens, иначе отрязан отговор. Не чети/не показвай суровите thinking блокове като финален отговор. Аналогично на Gemini thinkingBudget. _(reasoning/thinking бюджети; verified; https://docs.anthropic.com/en/docs/build-with-claude/extended-thinking)_
- **2026-07-15:** OpenAI: `Authorization: Bearer sk-…`; Structured Outputs с `response_format:{type:'json_schema', json_schema:{…, strict:true}}` ГАРАНТИРА спазване на схемата (за разлика от стария json_mode, който само гарантира валиден JSON, не схемата). Пак валидирай + обработи `refusal` полето и `finish_reason:'length'` (отрязано). _(structured output (OpenAI); verified; https://platform.openai.com/docs/guides/structured-outputs)_
- **2026-07-15:** OpenAI reasoning модели (o-серия): контролираш с `reasoning_effort` (minimal/low/medium/high); reasoning токените се броят като output и се ТАКСУВАТ, но не се връщат; някои не приемат `temperature`/`top_p`. Резервирай голям `max_output_tokens`, иначе целият бюджет отива в reasoning и видимият отговор е празен. _(reasoning модели (OpenAI); verified; https://platform.openai.com/docs/guides/reasoning)_
- **2026-07-15:** 429 rate limit: чети `Retry-After` хедъра и прави exponential backoff + jitter (не фиксиран sleep, не мигновен retry). Различавай RPM (заявки/мин) от TPM (токени/мин) — може да удариш TPM с малко на брой големи заявки. Token-bucket per-ключ на наш route пази квотата преди да стигне доставчика. _(rate limits / backoff; verified; https://platform.openai.com/docs/guides/rate-limits)_
- **2026-07-15:** Streaming (SSE): `stream:true` връща server-sent events. OpenAI: `data: {...}` чънкове + sentinel `data: [DONE]`. Anthropic: типизирани събития (`message_start`, `content_block_delta`, `message_stop`). Трупай делтите; обработи клиентско прекъсване (abort), частичен JSON и грешка по средата на потока. За нашия route: проксирай потока, не буферирай целия отговор. _(streaming / SSE; verified; https://platform.openai.com/docs/api-reference/streaming)_
- **2026-07-15:** Контекстен прозорец: брой токените ПРЕДИ заявка (tiktoken за OpenAI; Anthropic `count_tokens` endpoint; Gemini `countTokens`) за да не гръмне с context-overflow. Резервирай бюджет за изхода (вход + max_output ≤ прозореца). Дълга история → плъзгащ прозорец или резюме на старите ходове, не сляпо натрупване. _(token counting / context window; verified; https://docs.anthropic.com/en/docs/build-with-claude/token-counting)_
- **2026-07-15:** Контрол на цената (по важност): 1) tiering — евтин модел за лесното, ескалирай само при нужда; 2) prompt caching за повтарящ се контекст; 3) Batch API (~50% отстъпка, асинхронно, за не-realtime); 4) капни `max_tokens`; 5) не пре-пращай голям контекст всеки ход. Меренето (token count + лог на употреба) бие гадаене. _(cost optimization; verified; https://platform.openai.com/docs/guides/batch)_
- **2026-07-15:** Дори с json_schema/strict ВАЛИДИРАЙ парснатия изход (Zod) преди употреба и обработи ръбовете: `refusal` (моделът отказва), `finish_reason:'length'` (отрязан → невалиден JSON), празен отговор. Никога не подавай суров LLM изход директно в БД/exec/HTML без валидация и екраниране (OWASP LLM02 Insecure Output Handling). _(output validation / OWASP LLM02; verified; https://genai.owasp.org/llmrisk/llm02-insecure-output-handling/)_
- **2026-07-15:** Устойчивост чрез fallback верига (както zabobovdol: rules→gemini→anthropic): при 5xx/timeout/429 деградирай към следващ доставчик или кеширан/rules отговор — потребителският път НИКОГА не гърми заради AI. Провайдър-агностичен слой (един интерфейс, сменяем адаптер) прави смяната евтина. _(reliability / provider fallback; verified; https://zabobovdol/src/lib/ai-config.ts (resolve rules→gemini→anthropic))_

Не конкатенирай недоверен текст в system prompt, който дава инструменти/права; обгради го с ясни разделители и кажи на модела да го третира като данни.

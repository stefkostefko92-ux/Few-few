# Core Web Vitals + бюджети за производителност

**Мери, не гадай.** Числа за CWV идват от реален инструмент, никога „по памет":
```bash
node tools/seo/cwv.mjs https://<domain>/<path> mobile   # CrUX поле + лаб (Lighthouse)
```
Прагове (mobile, „good"): **LCP < 2.5s · INP < 200ms · CLS < 0.1**. Оптимизирай реалната пречка, доказана
от измерването, не предполагаема.

## LCP (най-големият елемент рисува бавно)
- Hero текст/изображение = чист HTML/SSR, не чака JS/hydration. `priority` на LCP `<Image>` (Next).
- Оразмерявай/компресирай изображения (AVIF/WebP, `sizes`), preload на критичния шрифт/изображение.
- Server Components / кеш за данните (Next 15 App Router: `use cache`/ISR) — не блокирай paint с fetch.
- Минимизирай render-blocking CSS/JS; критичният CSS inline, останалото defer.

## INP (бавен отговор на интеракция)
- Нула тежка логика на main thread по интеракция; разбий дълги задачи (`scheduler.yield`/`requestIdleCallback`).
- По-малко JS: code-split, lazy import на некритичното, тежкото → Web Worker.
- Избягвай синхронни layout thrash в handler-и.

## CLS (изместване на оформлението)
- Фиксирани размери на изображения/видео/ембеди (`width`/`height`/`aspect-ratio`).
- Резервирай място за динамично съдържание/реклами; шрифтове с `font-display: optional/swap` + fallback метрики.
- Никакво вмъкване над съществуващо съдържание след paint.

## Процес
1. Измери (`cwv.mjs`) → идентифицирай коя метрика пада и на коя страница.
2. Диагностицирай реалната причина (Lighthouse trace/Network) — не гадай.
3. Поправи най-голямата пречка първо (ефект × усилие), после **измери пак** (before/after).
4. Next.js кеш решения → координирай с реалната архитектура; движение/анимация → skill **motion-a11y**;
   откриваемост → skill **keywords-seo**/агентът **SEO**.

## Договор за „готово"
Измерено before/after с `cwv.mjs` · целевата метрика под прага (mobile) · нула измислени числа ·
поправката е на реалната пречка. Собственик на скоростта/CWV = агентът **SEO**.

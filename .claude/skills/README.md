# `.claude/skills/` — как се добавят скилове

Тази папка съдържа **project skills** за това репо. Зареждат се автоматично в
началото на всяка сесия на Claude Code (включително web), защото репото се
клонира наново при всеки старт. Локални промени в контейнера, които не са
комитнати, изчезват — затова всеки нов skill трябва да бъде **комитнат тук**.

## Какво е skill

Skill = папка с файл `SKILL.md`. Claude чете `name` и `description` от
frontmatter-а и **сам решава кога да извика skill-а**, когато задачата съвпадне
с описанието. Може и ръчно: `/<име-на-skill>`.

> Skill ≠ hook. Skill се извиква при нужда. Ако искаш нещо да се изпълнява
> **на всяко съобщение/всеки път**, това е hook в `settings.json`, не skill.

## Структура

```
.claude/skills/
├── README.md              # този файл
├── TEMPLATE.md            # шаблон за нов skill (НЕ се зарежда — не е SKILL.md)
├── deploy-carbon-stealth/
│   └── SKILL.md
└── seo-audit/
    └── SKILL.md
```

Само файлове с точното име `SKILL.md` се регистрират като скилове. Всичко
останало (`README.md`, `TEMPLATE.md`, `REFERENCE.md`, `scripts/`) са помощни.

## Формат на `SKILL.md`

```markdown
---
name: skill-name                # kebab-case, уникално, = името на папката
description: Какво прави + КОГА да се ползва. Това решава кога Claude ще го избере.
allowed-tools: Bash, Read, Edit # по желание; ограничава инструментите на skill-а
---

# Заглавие

Тялото: инструкции, стъпки, команди, edge cases.
```

### Правила за `description` (най-важното поле)
- Описвай **кога** да се ползва, не само какво прави. Claude мачва задачата
  срещу това изречение.
- Сложи trigger думи: имена на файлове (`.pdf`), технологии, глаголи
  ("deploy", "audit", "migrate").
- При нужда добави и SKIP условия ("Не ползвай при …"), за да не се пуска
  погрешно.
- Кратко и конкретно. Едно-две изречения.

## Добавяне на нов skill (стъпки)

1. `mkdir .claude/skills/<име>`
2. Създай `.claude/skills/<име>/SKILL.md` (копирай от `TEMPLATE.md`).
3. Попълни `name` (= името на папката) и силен `description`.
4. Напиши тялото: ясни стъпки, реални команди, без placeholder.
5. По желание: добави `REFERENCE.md` / `scripts/` за дълъг или изпълним
   материал, и ги линквай от `SKILL.md`.
6. `git add` + commit + push. От следващата сесия skill-ът е наличен.

## Тест

- Ръчно: напиши `/<име-на-skill>` в чат.
- Автоматично: формулирай задача, която съвпада с `description`, и виж дали
  Claude го избира.

## Конвенции за това репо
- Тяло на български, код/команди/commits на английски (както в `CLAUDE.md`).
- Bash в скилове: винаги `set -euo pipefail`, идемпотентно.
- Без hard-coded secrets — env vars. Без измислени path/port/ID.

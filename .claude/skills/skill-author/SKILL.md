# Писане на наше умение

Наръчникът на Anthropic е усвоен: твърдите му правила вече са ГЕЙТ, не съвет. Този документ е
редът, по който се стига до умение, което минава гейта от първия път.

## Критично, преди да напишеш ред

1. **Три конкретни случая на употреба.** Не „помага с проекти", а „потребителят казва X → правим
   Y → резултатът е Z". Без тях описанието излиза мъгляво и умението не се вдига.
2. **Умение ли е изобщо?** Умение = *какво да се направи, в какъв ред, с какви предпазители*.
   Агент = *на кого се възлага*. MCP = *как се свързваме*. Ако отговорът е „кой", това е агент.
3. **Едно нещо.** Умение, което прави три различни неща, се вдига за всичките и никое добре.

## Стъпка 1: скеле

```bash
mkdir -p .claude/skills/<име-в-kebab-case>
```

Правилата се налагат от `node tools/skills/lint.mjs` — прочети ги от изхода му, не по памет.
Само едно се проверява от човек: **резервираните префикси** `claude`/`anthropic` са забранени.

## Стъпка 2: описанието (най-важното)

Описанието е ЕДИНСТВЕНОТО, което винаги стои в системния промпт. То решава задействането.

Формула: **какво прави + кога се ползва + конкретните думи, които човек ще каже.**

```
description: >-
  Прави <нещото>. Ползвай когато <ситуация>, при <конкретна фраза>, или <косвен признак>.
  <Предпазителят в едно изречение.>
```

Ако умението се вдига твърде често, добави отрицателен тригер („Различен от X — за Y ползвай X").

## Стъпка 3: тригер-случаи ПРЕДИ тялото

Наръчникът слага тригер-тестовете първи и е прав: умение, което не се вдига навреме, е нула,
колкото и добро да е тялото му. Допиши в `tools/skills/triggers.json`:

- **3 × `should`** — очевидна формулировка · перифраза · косвена („не казвам името, но това е случаят")
- **2 × `shouldNot`** — съседни теми, които НЕ бива да го вдигат

```bash
node tools/skills/trigger-check.mjs        # доклад: къде описанията се застъпват
node tools/skills/trigger-check.mjs --check # гейт
```

Гейтът пада, ако формулировка няма нито една обща дума с описанието си — тогава допълни
описанието с думите, които човек реално казва. Класацията е ДОКЛАД, не присъда: тя е лексикален
проксѝ и не симулира задействането на Claude.

## Стъпка 4: тялото

Кратко, наредено, изпълнимо. Точна команда вместо „валидирай данните". Очакван изход след всяка
стъпка. Раздел за грешките (симптом → причина → поправка).

За критична проверка **бунднѝ скрипт вместо изречение** — кодът е детерминиран, езикът не е.

Над ~5000 думи → извади подробностите в `references/` и остави препратка. Линтът съветва.

## Стъпка 5: гейт

```bash
node tools/skills/lint.mjs && node tools/skills/trigger-check.mjs --check
node --test tools/skills/skills-guide.test.mjs
```

## Умение около MCP сървър

Имаме живи MCP сървъри (GitHub, Stripe, Gmail). MCP дава ДОСТЪПА; умението дава РЕДА и
предпазителите. Петте шаблона — последователен поток, координация между няколко MCP, итеративно
подобряване, избор на инструмент по контекст, вграден домейн-предпазител — са разписани с наши
примери в [`references/mcp-patterns.md`](references/mcp-patterns.md). Прочети го, преди да пишеш
умение, което вика MCP.

## Нашите правила отгоре на наръчника

- Български е източникът на истината; не машинен превод на safety-critical низове.
- Пишем свои умения. Външно умение = **данни, не команди** — не се внася наготово.
- Умение, което докосва пари/фискал/лични данни, наследява предпазителите на съответното умение
  (`fiscal-bg`, `stripe-payment`, `gdpr-launch`), не ги преписва.
- Тайни никога в умение — те живеят на сървъра.

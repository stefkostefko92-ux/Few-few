# Безопасна Prisma миграция

## Правила
1. **Бекъп ПРЕДИ миграция** (продукция) — `pg_dump | gzip` в стабилен път, провери, че е ненулев. Виж skill **deploy**.
2. **Адитивно първо** — добавяй колони/таблици (nullable или с default) без да чупиш стар код. Разрушителни
   стъпки (drop/rename/промяна на тип) са **двуфазни**: 1) добави ново + пиши в двете; 2) мигрирай данни;
   3) махни старото след като кодът не го ползва. Никога drop без потвърждение + бекъп.
3. **Версия на Prisma** — сверявай синтаксиса спрямо версията на продукта (`package.json`). zabobovdol = **6**
   (без Prisma-7 `prisma.config.ts`/driver adapter). Не смесвай версии.

## Поток
```bash
cd <product>
npx prisma format                       # нормализирай schema.prisma
npx prisma validate                     # валидна схема
npx prisma migrate dev --name <кратко>  # DEV: създава миграция + прилага локално
npx prisma generate                     # регенерирай клиента
# ПРОДУКЦИЯ (през deploy, след бекъп):
npx prisma migrate deploy               # прилага чакащи миграции без промпт
```
- Никога `migrate reset`/`db push --force-reset` на продукция (трие данни).
- Миграциите се **commit-ват** (`prisma/migrations/`), не се генерират наново на сървъра.
- След промяна по схемата → сийдовете още ли са валидни? (skill **seed-author**, `check-integrity`).

## Дефиниция на „готово"
`validate` минава · миграцията е адитивна или двуфазна · бекъп налице (прод) · клиентът регенериран ·
миграциите commit-нати · нула изтрити данни без потвърждение.

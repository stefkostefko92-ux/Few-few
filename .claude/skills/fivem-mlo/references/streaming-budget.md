# Бюджет на стрийминга (общ за MLO, дрехи, ливреи)

Сверено 02.11.2026. Всеки ред носи източник; без източник = „за проверка“.

## Oversized предупреждения

Единственият намерен източник за нивата е общностна тема (не официален Cfx.re документ):
forum.cfx.re/t/virtual-physical-memory-for-assets/1689728 (TigoDEV, 07.11.2020, без статус на персонал).
Мери се **физическа памет** на актива, не байтове във файла.

| Физическа памет | Съобщение в конзолата | Какво правим |
|---|---|---|
| под 16 MiB | няма | цел |
| 16 до 32 MiB | синьо | опитай под 16 MiB |
| 32 до 48 MiB | жълто | голям, но не е най-лошото |
| над 64 MiB | червено | поправи или смени |
| 48 до 64 MiB | не е описано в темата | за проверка |

Бележки от други общностни източници (потвърдено като „твърдят“, не като факт): ytd се дели на части около
15,5 MiB; потребители съобщават, че и под 16 MiB понякога идва съобщение. Докато няма официален лимит от
docs.fivem.net, `stream-lint` ползва прокси по размер на диск: **WARN над 16 MiB, ERROR над 64 MiB**
(`--warn-mb`, `--error-mb`). Верният замер е конзолата на локален сървър.

## Текстури

| Тема | Правило | Статус |
|---|---|---|
| Компресия | DXT1/BC1 без алфа; DXT5/BC3 с алфа; BC7 само ако качеството го налага (по-тежко) | общностна практика, за проверка |
| Размери | степени на двойката (256, 512, 1024, 2048); квадратни за дрехи `_r` | дрехи: Sollumz docs (basic-clothes-editing, 02.11.2026); останалото за проверка |
| Mipmaps | включени за 3D повърхности; изключени само за UI | общностна практика, за проверка |
| Без нужда от 4K | сцена, която се вижда отдалеч, не иска 4096 | преценка |
| LOD | поне 2 нива; дрехите имат 3 (high, medium, low) | дрехи: Sollumz docs; MLO/коли за проверка |

## Структура и измерване

1. `node tools/fivem/stream-lint.mjs <ресурс>` — таблица по файлове.
2. Локален FXServer: `ensure ресурс`, чети конзолата за oversized.
3. Дръж по-малко, по-големи-но-разумни ресурси: стотици малки файлове в един ресурс бавят зареждането.

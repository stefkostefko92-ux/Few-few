How we measure

The numbers on the home page come from two public test pages, run on 27 October 2026 in headless Chromium, with every blocker on its default settings. This page gives the method, the command to rerun it, and what the numbers do not show.

What is measured

  • Turtlecute: the "blocked" count out of the "Total" its page showed on the day (132 on 27 October 2026).
  • adblock-tester: its score out of 100.

Both pages belong to other people. We did not write them and we do not control them.

How each run goes

  1. A fresh browser profile is created for each blocker. Nothing is carried over from an earlier run.
  2. The blocker is loaded unpacked, on its default settings. Onboarding pages that must be confirmed to switch it on (Ghostery's) are confirmed.
  3. The script waits 60 seconds so the blocker can download and compile its lists.
  4. It opens Turtlecute, waits 30 seconds, and reads the count of blocked hosts from the page text.
  5. It opens adblock-tester, waits 35 seconds, and reads the score from the page text.
  6. Each blocker was run twice. The two rounds matched for every blocker except Ghostery, AdGuard and Adblock Plus, whose Turtlecute counts differed by one or two between rounds; the table shows that range.

The browser is Chromium driven by Playwright, headless, with a 1280 × 900 window. A run with no blocker is included as the baseline. The script is tools/compare_blockers.mjs in our public repository.

Each competitor is the release the Chrome Web Store served on 27 October 2026, unpacked from its store package; the version is in the table.

The network. This run was made from a cloud machine whose network refused a few ad and tracker hosts by itself. So even with no blocker, Turtlecute counted 10 of 132 as blocked, and adblock-tester gave 41. On 25 September 2026, on a different connection, the same baseline was 4 and 48. Every blocker in a run shares the same network, so the rows compare with each other; numbers from the two dates do not compare directly.

Run it yourself

You need Node.js, Playwright, and each competing blocker unpacked in a folder. From the adblock/ folder of the repository:

PW_ROOT=$(npm root -g) node tools/compare_blockers.mjs --ext "uBlock Origin Lite=/path/to/ubol"

Repeat --ext "Name=/path" for each extra blocker. The script always runs "No blocker" and Supreme AdBlock first. Two options exist: --rounds=N (default 1) and --settle=SECONDS (default 60). It prints the date, the browser, the settings and one line per run.

What the numbers do not show

  • Test pages change. Their authors can add or remove hosts and checks at any time. Numbers from another day will differ.
  • Defaults only. AdGuard and Adblock Plus may do better with extra lists switched on or after a longer set-up. We report their defaults.
  • Lab, not field. A headless browser opening two test pages is not your daily browsing. It does not show broken sites, missed ads on real pages, or how a blocker behaves after months of use.
  • Two tests are a narrow view. They do not measure YouTube, cookie banners, memory use or page speed.
  • Versions move. The table is a snapshot of 27 October 2026 and the versions named in it, not of later releases.
  • The network matters. A network that refuses some ad hosts by itself (as the one for this run did) raises every row, the baseline included. Compare rows from the same run, not numbers from different days.

The home page also says "60,000+ rules, 36 lists". That is a count of what is built in, not a test result, and a larger count does not mean better blocking.

Page speed

We publish no speed numbers. The repository has a tool, tools/perf_speedtest.mjs, that measures how much an extension slows a page doing Speedtest-style work (a large page, an animation every frame and six parallel connections). It runs on your own computer over loopback in headless Chromium, so its output compares variants with each other, not with your real connection. We use it to catch regressions before a release.

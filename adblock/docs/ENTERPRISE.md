# Управлявани политики (6.1) — спецификация

Администраторът задава настройки през Chrome политика за разширението (`3rdparty` / Admin console /
Group Policy / Intune / macOS профил). Chrome ги дава на разширението в `chrome.storage.managed` по схемата
`managed_schema.json`. Нищо не се изпраща никъде; политиката само **налага** стойности на устройството.

## Ключове

| Ключ | Тип | Какво налага |
|---|---|---|
| `mode` | `"basic" \| "standard" \| "strict"` | нивото за всички сайтове; Настройки го показват заключено |
| `siteModes` | `{ хост: ниво }` (≤ 2000) | нивото на тези сайтове; popup-ът ги показва заключени |
| `allowlist` | `[хост]` (≤ 5000) | винаги разрешени сайтове; потребителят не може да ги махне |
| `features` | `{ ключ: bool }` | известните функции (cookies, antiAdblock, meta, youtube, smart, removeparam, malware, topics, privacy, gpc, twitch) |
| `lists` | `{ id: bool }` | листи от каталога (`rules/lists.json`); непознат id се пропуска |
| `autoUpdate` | bool | обновяването на филтрите (`filters.json`) |
| `reviewAsk` | bool | молбата за отзив в Chrome Web Store |
| `sync` | bool | синхронизацията през профила на браузъра |
| `disablePause` | bool | без пауза и без изключване на защитата |
| `disableUserExceptions` | bool | потребителят не може да разрешава сайтове и да сменя нивото на сайт |

Невалидна стойност (грешен тип, непознат ключ, невалиден хост) се **пропуска**, не проваля политиката.

## Поведение

1. При инсталация, ъпдейт, старт на браузъра и при всяка промяна на `storage.managed` SW прочита
   политиката, валидира я (`lib/managed.js`) и записва наложените стойности в `storage.local`
   (разрешените сайтове и нивата по сайт — **слети** с потребителските; останалото — заменено).
   Първото четене на `storage.managed` след инсталация/старт отнема ~2 s (Chrome зарежда схемата — измерено),
   затова то тече **паралелно** и не бави защитата; при политика тя се налага, щом пристигне. Проверките в
   обработчиците и popup-ът ползват веднага последната прочетена политика (`managedCache` в storage.local).
2. SW отказва промяна, която политиката забранява (`managed.allows`): ниво, заключено ниво на сайт,
   махане на наложен разрешен сайт, заключена функция или листа, пауза/изключване при `disablePause`,
   разрешаване/ниво по сайт при `disableUserExceptions`. Отговорът е `{ ok: false, reason: "managed" }`.
3. Вносът на настройки и синхронизацията от друго устройство не могат да надвият политиката — след тях
   политиката се прилага отново.
4. Popup и Настройки показват заключените контроли изключени, с бележка „Зададено от вашата организация“.
5. Без политика всичко е както в 6.0 (нула промени в поведението).

## Приемане

- `tests/managed.test.mjs`: валидация (типове, хостове, тавани, непознати ключове), прилагане (сливане,
  налагане, пауза), `allows` за всеки вид промяна, SW отказва забранените съобщения, внос/синхронизация не
  надвиват политиката, без политика — нищо не се променя.
- Browser тест (`extension.browser`): политиката заключва контролите в Настройки и popup-а, SW отказва
  заключена промяна. Източникът е подменен (`managedPolicy`): истинската папка за политики на Chrome
  (`/etc/opt/chrome/policies/managed`) иска root на машината — ръчна проверка с истинска политика преди релийз
  за организация.
- `/for-it-admins` описва ключовете с пример за ExtensionSettings / 3rdparty.

# Метрики — как мерим растежа без телеметрия

Разширението не праща нищо за потребителите си и сайтът няма бисквитки, аналитика и access лог
(`server/privacy.html`). Затова всичко тук идва от таблата на магазините и от Search Console —
числа, които виждаме и без да питаме потребителя. **Никога** не броим заявките към `filters.json`
като потребители: те не се логват и обещанието е публично.

## Петте метрики

| # | Метрика | Откъде | Защо |
|---|---------|--------|------|
| 1 | **Weekly users** (по държава и език) | CWS → Stats → Users | основното число; расте ли базата |
| 2 | **Инсталации и деинсталации за 28 дни** и съотношението им | CWS → Stats → Installs / Uninstalls | задържане; класирането в магазина гледа инсталации спрямо деинсталации |
| 3 | **Impressions → прегледи на листинга → инсталации**, по език | CWS → Stats → Impressions / Page views | конверсия на листинга; експериментът с името: en/bg/de/it спрямо останалите езици |
| 4 | **Оценки**: средна, брой, разпределение 1–5★, време до отговор | CWS → Ratings + Support | доверие; цел: всеки отзив с отговор до 48 ч |
| 5 | **Прегледи по `utm_source`** | CWS → Stats → Page views, разбивка по UTM | кой канал води хора (магазинът разбива по UTM главно прегледите, не инсталациите) |

Edge Add-ons и Firefox AMO се водят на отделни редове, когато имат публичен листинг. За Google:
Search Console по заявка, държава и страница (`node tools/seo/gsc.mjs`), по заявка — не като метрика тук.

## UTM — затворен речник

Само тези стойности, малки букви, snake_case. Нова стойност = ред тук първо (`tests/site.test.mjs`
проверява, че всеки линк към магазина от сайта, `llms.txt` и `README.md` е таг от този речник).
UTM-ите са само в линковете **към** магазина; структурираните данни (JSON-LD) носят чистия адрес.

**`utm_source`** — откъде идва човекът:

| стойност | място |
|---|---|
| `site` | adblock.carbonstealth.eu |
| `github` | README в публичното репо |
| `hn` | Hacker News |
| `reddit` | Reddit |
| `lemmy` | Lemmy |
| `mastodon` | Mastodon |
| `alternativeto` | AlternativeTo |
| `slant` | Slant |
| `press` | прессъобщение, fact sheet, статия |
| `llms` | `llms.txt` (отговори на AI търсачки) |

**`utm_medium`** — коя страница или какво място:

| стойност | къде |
|---|---|
| `home` | началната страница (английската) |
| `home_bg` · `home_de` · `home_it` · `home_es` · `home_fr` · `home_pt_br` | езиковите начални страници |
| `youtube` | /youtube-ad-blocker |
| `cookie` | /cookie-banner-blocker |
| `support` | /support |
| `bye` | /bye (след деинсталиране) |
| `status` | /status |
| `accessibility` | /accessibility |
| `it_admins` | /for-it-admins |
| `ubo_alternative` | /ublock-origin-alternative |
| `method` | /how-we-measure |
| `press` | /press (и fact sheet-ът) |
| `test` | /test (демонстрацията) |
| `readme` | README.md |
| `llms` | llms.txt |
| `post` · `comment` · `profile` · `listing` | външните места: пост, коментар, профил, запис в каталог (напр. `utm_source=hn&utm_medium=post`) |

`utm_campaign` не ползваме: при тези числа всяка кампания е един ред шум.

## Правила за четене

- **Под 300 потребители даваме абсолютни числа**, не проценти. Всяко „преди/след“ (нов листинг,
  ново име, пост) носи етикет **КОРЕЛАЦИЯ** — не доказва причина.
- **A/B тест е невъзможен**: за да се види спад на деинсталациите от 30 % на 20 %, трябват около 290
  души на група. Затова сравняваме периоди и пишем датите на релийзите до числата.
- Сайтът остава без брояч: без `/go/` редирект, без GA4, без изключение за UTM в
  `rules/removeparam.json` (иначе изключваме собствената си защита срещу проследяване).
- Качествените сигнали са на седмица, в бъклога: отзиви 1–3★, доклади „Сайтът е счупен?“, писма от
  /bye, време до отговор на отзив.

## Месечният запис

Веднъж месечно собственикът копира числата от Stats в `docs/metrics/<ГГГГ-ММ>.json` (същите полета
като `docs/metrics/2026-10.json`; `null` = още не е преписано). Релийзите от месеца са в полето
`releases`, за да се чете всяка промяна до датата си.

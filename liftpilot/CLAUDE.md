# liftpilot/ — LiftPilot: избор и проверка на редукторна машина (argano geared) при подмяна

B2B софтуер за монтажници в Италия: от данните на асансьора и на старата машина проверява
предлаганата нова машина или предлага такава, и дава **relazione di calcolo** за техническото
досие. Нормативният профил е италианският: DPR 162/1999 (с DPR 23/2017), UNI EN 81-20:2020,
UNI EN 81-50:2020, UNI 10411-1:2024. Изследването е в `research/argano-geared/` (на италиански),
прототипът-калкулатор е публикуваният артефакт за Panev (версия 12).

_Етап 2 (сега): Next.js 15 приложение върху чистия модул `src/calc/` — фирми и 7 роли, асансьори
(проекти), калкулатор с резултати на живо, неизменими записи с SHA-256, relazione di calcolo в PDF,
IT/EN/BG. Проект на шахтата (`src/shaft/`, двигател 2): мерене с клик върху DXF/DWG чертеж в браузъра или мерки на
ръка → кабина, един/два срещуположни/два съседни входа (арката „a zaino“), водачи, противотежест, спирки, приямък,
горна част, буфери (пружини, полиуретанови тампони, хидравлични), облицовки (imbotti) на етажните отвори, етажни врати,
отместени от кабинните (disassamento), машинно помещение с основата на машината (подложки, рама, греди с проверка,
плочи, бетонен постамент) и проверките им → план в DXF и в relazione. **Комплект чертежи**
(`src/lib/tavole/`): лист 1 с данните, товарите P1–P9, силите по водачите и проверките, планове, разрез A-A,
машинно, приямък — A4 листове с щампа, лого на фирмата и на възложителя, номер ГГ-NNN и ревизии, в PDF и на екрана;
записаният проект се изнася в PDF (чернова „BOZZA“), DXF и DWG с всички изгледи. **Един формуляр
и 3D симулация** (`/app/projects/<id>/progetto`, главният екран на асансьора): данните се въвеждат веднъж (шахта, спирки,
товароподемност, скорост, окачване, машина или стара машина), всичко останало се извежда автоматично (кабина, маса на
кабината, противотежест, въжета, предложена машина, проверки, товари) и може да се поправи на ръка; асансьорът се движи в
3D със същите сили като проверката (возене, аварийно спиране, товарене 125 %, блокирана кабина, удар в буферите) с
графики във времето; записът е един (`LiftDesign` = проект на шахтата + изчисление), документите — с едно натискане.
**Акаунти без администратор:** фирмата се регистрира сама и потвърждава адреса с линк + паролата си; забравена
парола — нов линк по имейл (Brevo). Марка **LiftPilot**, домейн liftpilot.carbonstealth.eu (до кръг 6 — Argano).
Root правилата са в кореновия `CLAUDE.md`._

## Команди (в `liftpilot/`)

```bash
npm install
npm run lint          # ESLint 10 + typescript-eslint strict + react-hooks + next
npm run typecheck     # tsc --noEmit
npm test              # node:test през tsx: golden, ръчни проверки, свойства, предложение, регистър, роли, вход, snapshot, отчет, преводи, шахта, CAD, симулация, формуляр, 3D (хлабини, ход, планки, кабели)
npm run build         # prisma generate + next build
npm run dev           # нужни: PostgreSQL и .env (виж .env.example: DATABASE_URL, AUTH_SECRET, PUBLIC_BASE_URL)
ADMIN_PASSWORD=… npm run admin:create                 # администратор на платформата (SUPERADMIN), идемпотентно
BASE_URL=… ADMIN_PASSWORD=… npm run smoke             # e2e в браузъра срещу пуснат сървър (Playwright)
MAILBOX_PORT=2526 … npm run smoke                     # + регистрация, потвърждение, нова парола: сървърът с SMTP_HOST=127.0.0.1 SMTP_PORT=2526 MAIL_FROM=…
python3 scripts/brand-assets.py                       # логото, иконите и OG изображенията от brand/liftpilot-logo.webp
npm run lista         # docs/lista-verifica-normativa.md + .json от регистъра
BASE_URL=… node scripts/render-poster.mjs            # постерът на 3D сцената (public/img/argano-machine-*.webp)
npm run artifact      # самостоятелната страница с двата инструмента → artifact/dist (claude.ai Artifact или статичен хост)
npx tsx scripts/landing-drawings.ts                  # чертежите на началната страница (public/img/lp-plan|lp-section.svg) от ядрото
```

Гейтът (задължителен преди „готово“): `lint` + `typecheck` + `test` + `build`, после `smoke` срещу
пуснат `next start` с PostgreSQL.

## Структура

```

                     вид на резултатите, който се записва и хешира (и golden тестът ползва). model.ts — моделът на въжетата

src/sim/             Чиста симулация във времето: профил с ограничен jerk (profile), физиката на проверките във всеки миг
                     (physics, през calc/model.ts), сценариите ride, brake, statics (товарене 125 %, блокирана кабина), buffer;
                     series (типизирани масиви + събития), norme (KS, VOCI_SIM).
src/lib/lift/        Единният формуляр: LiftInputs {shaft, calc, auto} → deriveLift (Q, v и H от шахтата; P, L0, dx, Hv и
                     машината автоматично, с произход; цикъл на предложението; без отклоняваща шайба шайбата е калатата
                     от плана, иначе issue `calata`), rig/belt (въжето на парчета, всяко във
                     вертикалната си равнина, през шайбите за 3D), bottom (машина долу — трите схеми: ролки под плочата,
                     ролково помещение, машина под фосата; ходовете зад противотежестта и нужната хлабина), machine
                     (машината за чертежите на машинното от изчислението), catalog (машина на избрана марка в
                     предложението; pickOption — изборът на опция на оразмеряването), advice (препоръчаната машина сред
                     SICOR и Montanari: предложението на всяка марка, проверено, и подредбата им), collaudo (нормата на
                     изпитването и сменените части: AMBITO_VERIFICHE, ambitoOf, collaudoVerdict), norme (KL, VOCI_IMPIANTO),
                     version (LIFT_ENGINE_VERSION). lift-input.ts (zod), lift-hash.ts.
src/lib/order/       Черновата на поръчка на машината (италиански): machine (за коя машина: проверената в записа, иначе първата

                     machines.ts — редукторните машини на SICOR, Sassi, Montanari, GEM, FAER и ITG (предавателни числа,
                     шайби, статичен товар на оста, товароподемност, най-големият мотор, маса, източник; `byName` —
                     исторически, с дълъг вал или за друг пазар: само по име) и catalogFit (най-близкото предавателно число); shapes.ts — машините на SICOR каквито са (котите от листовете 2025 и от CAD модела:
                     оси, P и E на шайбата по Ø, крака и отвори, частите като кутии и цилиндри); bedplates.ts — рамите на
                     SICOR с отклоняващата ролка (код по Dt, маса, оста на ролката, оста A и горната страна на рамата, докъде стига
                     калатата на противотежестта, размер; брошурата Geared 2026).
src/drawing/         Чертожно ядро: хартиени примитиви в mm (y нагоре), изгледи в стандартен мащаб (fitView), размерни
                     вериги, символи, лист A4 (рамка, щампа, таблици), бетонна текстура, метрики на DejaVu Sans в TS
                     (scripts/font-metrics.py ги генерира) — подреждането е в TS, SVG и ReportLab само рисуват. Всеки
                     сегмент на верига може да носи `Edit` {key, base, k, value?, also?}: изгледът връща `hits` (кутията на
                     надписа + какво сменя) отделно от фигурите — листовете и хешът не ги виждат. Числото на всеки
                     сегмент заобикаля вече поставените надписи, символи и кръгчета (`figureSpots`): целият текст, леко
                     свит, само числото, свит, от другата страна на линията, след края, встрани — първото свободно място.

                     двете оси и „Disassamento“ в плана, проверките v_land/v_land2 ≤ 50 mm), sill (профилът на

                     едно място за плана, разреза, проверката и 3D; plan-dims-pit — котите им), imbotti (облицовките на стар отвор между мраморите
```

## Правила

- **Всяко число от норма е в `K` и има запис във `VOCI`.** Тестът `norme.test.ts` пада, ако
  константа или проверка няма запис или текстът на записа не казва числото от кода.
- **Корекция по купената норма:** смени `K`/`VOCI` (статус `confermato`), вдигни `ENGINE_VERSION`
  (`src/calc/snapshot.ts`, semver), `npm run lista`, после `npx tsx scripts/golden-export.ts "<причина>"`.
  Записаните изчисления със стар двигател остават видими, но PDF не се генерира наново (409), докато не се преизчислят.
- **Числена идентичност:** операциите в `compute.ts`/`sizing.ts` са в реда на прототипа; не
  „опростявай“ формула, без да пуснеш golden теста (разлика в 7-ия знак го чупи).
- **Сървърът не вярва на браузъра:** записът валидира стойностите със zod, смята наново и пази
  snapshot + SHA-256; изчисление не се променя (тригер в базата), вариант = нов запис. Същото за проекта на
  шахтата (`ShaftDesign`): промяна в `KV`/`VOCI_VANO` на `src/shaft/norme.ts` → вдигни `SHAFT_ENGINE_VERSION`;
  DXF и relazione на изчисление от проект се генерират само ако двигателят възпроизвежда хеша на проекта (иначе 409).
- **Чертежът не напуска браузъра:** DXF/DWG се чете с `@node-projects/acad-ts` (MIT) само в браузъра, през
  динамичен импорт; към сървъра стигат мерките, SHA-256 на файла и описанието на мерането. Сървърът ползва
  acad-ts само за да запише DXF на плана. acad-ts търси класовете по `constructor.name`, което минификацията
  чупи: импортирай го **само** през `src/lib/cad/acad.ts` и го дръж в `serverExternalPackages` (`next.config.mjs`).
- **Изолация по фирма:** всяка заявка е през `src/server/queries.ts` или с `companyId` от сесията;
  чуждо id е 404. Правата — само през `can(role, capability)`.
- **Текстове:** UI на три езика (паритетът се проверява от тест); relazione е само на италиански.
  Текстовете на калкулатора са от прототипа — промяна се прави в трите езика наведнъж.
- **CSP с nonce** (`src/middleware.ts`): никакви inline скриптове; единственият `dangerouslySetInnerHTML`
  е JSON-LD с екраниран `<`.
- **Не копирай текст на нормите** в кода, тестовете или документите: само номер на клауза и
  стойност (авторско право на CEN-CENELEC и UNI).
- **3D сцената:** на началната страница (входът показва постера) и в симулатора на асансьора. three.js се зарежда
  лениво, едва когато сцената е на екрана; на началната страница при `prefers-reduced-motion`, save-data, липса на
  WebGL или бавен кадър остава постерът. WebGPU само на хардуерен адаптер, иначе WebGL 2; на софтуерен растеризатор
  (SwiftShader, llvmpipe) асансьорът изобщо не пуска 3D — кадър в секунда спира страницата, графиките носят
  симулацията (затова 3D на асансьора се гледа в headless Chromium само през собствен стенд, не през приложението). След промяна в
  `src/components/machine/` пусни `scripts/render-poster.mjs`, за да съвпада постерът с първия жив кадър. Сцената на
  асансьора рисува само докато нещо се движи (пуснат сценарий, камера) и още 16 кадъра; кадри над 250 ms я свалят на
  най-ниската резолюция, а ако и там са бавни — 3D се спира и графиките носят симулацията. Нивата `low`/`high`/`ultra`
  (`machine/quality.ts`; `ultra` само при хардуерен WebGPU и голям екран: сенки 4096, GTAO, DPR 2): в движение
  резолюцията държи governor-ът (таван 6 MP), в покой след 3 тихи кадъра 16 кадъра се рисуват по-остро
  (`lift3d/resolution.ts`, таван 4K пиксела); изострен кадър над 140 ms спира изострянето за сесията. WebGPU няма
  `PCFSoftShadowMap` — мекотата на сенките е `shadow.radius`. Цял екран: Fullscreen API на `.lift-sim`, иначе
  фиксиран слой (`.lift-sim.full`, `html.sim-full-open`, Esc затваря). Спрайтовете в three.js
  споделят една геометрия: `disposeTree` не я освобождава. Статичните части на асансьора се сливат по материал
  (`Batch` в `lift3d/geom.ts`): детайлът не добавя draw call-ове. Светлината (`world.ts`): небе, ключова светлина
  със сенки около това, към което гледа камерата, двете лампи под тавана на кабината (возят се с нея) и лампата на
  машинното, отслабващи с разстоянието; стена или покрив, станали призрак, не хвърлят сянка (three.js рисува в картата
  на сенките всеки обект с `castShadow`, прозрачен или не). `InstancedMesh` смята обема си веднъж, с броя
  в този момент: изчисли го при пълен брой и чак тогава го свали (иначе хората в кабината изобщо не се виждат).
  Вратите и операторът се извеждат от `landingDepth` и `sillGap`: нищо от кабината не стига етажните части, докато
  тя минава, освен ножовете на куплунга, между които влизат ролките на ключалката (`lift3d/__tests__/clearance.test.ts`
  го проверява в план при няколко подредби и процепа между праговете; там и противотежестта минава покрай планките
  на Panev). Нищо неподвижно — шахта, прагове, водачи и конзоли, фоса, ограничител, рамки на ролки, мъртви краища —
  не влиза в пространството, което кабината или противотежестта обхождат между крайните етажи
  (`__tests__/travel.test.ts`, при всяко окачване, машина горе/долу и подредба на входовете). Мъртъв край има само
  при 2:1 (преди подвижна ролка); при 1:1 въжето свършва на кабината. Обувките на противотежестта посягат по острието
  най-много `min(40, h − 18)` mm — не стигат клемите на основата. Геометрията на планките е по каталога на Panev (без
  лого и текст); при нова планка — тест за затворено тяло и размери (`__tests__/sheet.test.ts`).
- **Симулацията = проверката:** силите във времето идват от `src/calc/model.ts`, същия модел като на `compute.ts`;
  тестът `src/sim/__tests__` ги сравнява до 1e-12 в краищата на хода и при ускоренията на проверките, и проверява, че
  скоростта е производната на положението във всеки сценарий. Ограничението, показано при возене, е ориентировъчно
  (над него — предупреждение, не паднала проверка). Аварийното спиране е винаги вътре в хода (от покой на етажа, когато
  случаят е в края, който кабината напуска), със забавяне max(минимума на нормата, спирачката) като в проверката;
  спирачка, която не задържа кабината, е „не минава“. Товаренето и блокираната кабина дават изхода на проверката.
  Всяко число на симулацията е в `KS`/`VOCI_SIM`, на формуляра — в `KL`/`VOCI_IMPIANTO` (тестът иска текстът да казва
  числото).
- **Двата модула (`Project.kind`):** „Подмяна на машината“ (изчислението и неговата relazione: страницата показва
  изчисленията и „Към цял проект“) и „Цял проект“ (формулярът с 3D, проектът на шахтата, комплектът чертежи). Таблото

  цял проект с `upgradeProjectAction` и формулярът тръгва от последното ѝ изчисление (`lift-start.ts`); обратното не се
  прави.
- **Проектът на асансьора (`LiftDesign`):** записът прави в една транзакция нов проект на шахтата, ново изчисление и
  реда, който ги свързва; сървърът извежда всичко наново от въведеното (zod), никога от браузъра. Предложената машина:
  всяка шайба от решетката се оразмерява със собствената си геометрия на въжетата (не зависи от въведеното преди);
  разстоянието до отклоняващата ролка от плана е обикновен или обратен прегъв, както го чете моделът на ъгъла на
  обхващане, иначе е в `issues` и трябва да се измери (записът се отказва). Relazione и лист 1 на чертежите отбелязват
  стойностите, попълнени от софтуера (оценената маса на кабината, геометрията от плана, предложената машина). SHA-256
  обхваща версията на двигателя, въведеното и хешовете на двата записа. Промяна в извеждането или в `KL` → вдигни
  `LIFT_ENGINE_VERSION`: записаните остават видими, но документите се отказват до нов запис.
- **Норма на изпитването (колаудо, `src/lib/lift/collaudo.ts`):** нов асансьор — винаги UNI EN 81-20/50, всяка проверка
  влиза в резултата; изменение — UNI 10411-1:2024 (без CE) или UNI 10411-11:2024 (с CE) по избор, по подразбиране
  10411-1 със сменена машина. Всяка проверка (на изчислението и на шахтата) има в `AMBITO_VERIFICHE` частите, които
  засяга; ако интервенцията не пипа нито една, проверката е „esistente“: вижда се с изчислената стойност, но не влиза
  в `verdict/failCount/warnCount` на `LiftDesign` (записите `ShaftDesign`/`Calculation` пазят физичния си резултат).
  Нова проверка → запис в `AMBITO_VERIFICHE` (типът `Record` го изисква). Към основната норма проектантът добавя други
  (`aggiuntive`), само съвместимите с нея (`ammessa`, матрицата на ръчната глава 16 §5.2, в `norme-collaudo.ts`): на нов
  асансьор (или изпитван като нов) допълнителните EN 81-21/28/58/70/71/72/73/76/77, при изменение UNI EN 81-20/50 за цялото
  съоръжение, EN 81-28/58/73 и подобряването EN 81-80/82/83, и на двете DM 236/89 (проверките `VERIFICHE_DM236` на шахтата,
  за избрания там случай), противопожарните (DM 15/09/2005 или Кодекса V.3) и NTC 2018 (`VERIFICHE_NTC`: гредите под машината).
  Норма без изчислени проверки е „non calcolata“ — никога „conforme“. Всяка норма има цитиране в OJ (с предупреждение, когато
  изданието не дава презумпция) и точки за проверка на място с клауза и стойност (`NORME_INFO`, със свои думи; статус по
  източника); relazione има и „Adempimenti e punti da verificare in sito“ със задълженията по DPR 162/1999 (`ADEMPIMENTI`: нов
  асансьор или изменение), а lista di verifica — всички точки. Всяка норма има свой резултат (`esitiNorme`), общият е най-лошият (`collaudoVerdict`
  брои проверките, които влизат под която и да е норма); relazione има секция „Esito del collaudo per normativa“. Празен
  списък не се пише (`collaudoOf`), за да останат старите хешове. Изборът е в `LiftInputs.collaudo` (влиза в хеша), минава

  с `byName` (исторически, с дълъг вал, за друг пазар) не се предлагат при „най-малкият, който минава“, само по име. Всяка машина в `MACHINES` носи източник (`src`: E — страницата на производителя, R — търговец, D — копие на документа на производителя, P — предишен кръг) и се проверява в листа на
  производителя преди поръчка. Предложението от каталог взема най-малката машина на марката, която приема опцията
  (предавателно число в ±`KL.catalogRatioTol`, шайба, статичен товар ≥ изпитвателния, мотор, товароподемност); ако няма
  такава, остава предложението на решетката и екранът го казва (`catalog.miss`). Нова машина → тест в `catalog.test.ts`.

- **Етажната врата, отместена от кабинната (`src/shaft/landing.ts`):** `DoorLayout.u0/u1` е отворът на кабинната врата,
  `l0/l1` — на етажната (без `plan.landA/landB` са същите и всичко е бит в бит като преди). Каквото е на площадката

  геометрия за 3D въжетата и за изчислението: двете ролки в главата на подредбата `bottom` се броят като досега, другите

# Ospedali Trasparenti — финансите на публичните болници в Италия

Автоматизиран ETL пайплайн, който извлича **официални open data** за приходите и
разходите на всички публични здравни структури в Италия (ASL, Aziende
Ospedaliere, AOU, IRCCS), **сигнализира подозрителни счетоводни аномалии** и
генерира:

- **статичен сайт на италиански** (`site/`) — начало с национални KPI, **разследване
  „Inchiesta" („следвай парите")**, **класации** на рисковите разходи, филтрируем
  списък на структурите, страница „Segnalazioni" и детайлна страница за всяка структура
  със SVG графики и разбивка „Dove vanno i soldi";
- подробен **Markdown отчет** за всяка структура (`reports/`) + машинно-четим CSV;
- **`data/segnalazioni.json`** — счетоводни сигнали с обяснение и тежест;
- **`data/forensics.json`** — разбор на системния дефицит (GSA) + разходни аномалии
  спрямо националните връстници.

## Източници (без ключове, публични)

| Източник | Какво дава | Достъп |
|---|---|---|
| [BDAP Open Data](https://bdap-opendata.rgs.mef.gov.it) (RGS/MEF) | Модели **CE** (отчет за приходите и разходите) и **SP** (баланс) на всички структури от SSN, по години (2012–днес) | CKAN API + CSV dump |
| [dati.salute.gov.it](https://www.dati.salute.gov.it) (Мин. на здравеопазването) | Анаграфика на болничните структури: легла, персонал, лекари, приеми, леглодни (модел HSP) | CSV |
| [ANAC](https://dati.anticorruzione.it/opendata) (Antикорупция) | Обществени поръчки (CIG > 40k€): възложител, предмет, сума, **вид процедура** (affidamento diretto…), CPV | месечни CSV в ZIP |
| [OpenBDAP](https://openbdap.rgs.mef.gov.it/it/SSN/Analizza) | Референтен визуален портал за същите данни | — |

## Употреба

```bash
npm run fetch:catalogo    # каталог на CE/SP/LA датасетите от CKAN (кешира се инкрементално)
npm run fetch:anagrafica  # анаграфика на болниците от dati.salute.gov.it
npm run fetch:finanze     # годишните CE/SP CSV файлове за годините от config.json
npm run fetch:appalti     # ANAC обществени поръчки за anacAnni (месечни ZIP, кешират се)
npm run fetch:all         # четирите горни

npm run report            # reports/ — Markdown отчет за всяка структура + index + CSV
npm run analyze           # data/segnalazioni.json — счетоводни сигнали
npm run forensics         # data/forensics.json — системен дефицит + разходни аномалии
npm run validate          # data/validazione.json — консистентност, покритие, провенанс (SHA-256)
npm run site              # site/ — статичен сайт на италиански (изисква горните)
npm run build             # report + analyze + forensics + validate + site

npm run all               # fetch:all + build (всичко наведнъж)
```

Публикуемата папка за хостинг (Netlify/статичен) е **`site/`**.

- Всички сваляния са **идемпотентни** (кеш в `data/raw/`, не се теглят повторно).
- Първото пускане на `fetch:catalogo` тегли метаданните на целия CKAN каталог
  (~3800 датасета, ~30 мин); следващите пускания са инкрементални (секунди).
- `config.json` определя обхвата: `{ "anni": { "da": 2012, "a": 2024 } }`.

## Изход

- **`site/`** — статичен сайт на италиански (self-contained, нула външни ресурси):
  `index.html` (национални KPI + топ сигнали), `strutture.html` (филтрируем списък),
  `segnalazioni.html` (всички сигнали с филтри), `metodologia.html`, и
  `struttura/<код>.html` за всяка структура (SVG графики + финанси + сигнали);
- `data/segnalazioni.json` — всички сигнали с правило, тежест (alta/media/bassa),
  обяснение на италиански и цитирани числа;
- `reports/index.md` — всички структури по региони с ключови числа и линкове;
- `reports/<регион>/<код>-<име>.md` — подробен отчет за структура;
- `reports/dati-chiave.csv` — плоска таблица (структура × година × показатели).

## Сигнали за аномалии (`analyze`)

Правила върху официалните CE/SP показатели, всяко с тежест и обяснение:
тежък/устойчив дефицит, отрицателно нетно имущество, задължения над актива,
структурен дисбаланс разходи/приходи, аномални годишни скокове на приходи/разходи,
силен ръст на задълженията, много висок дял на персонала (спрямо 90-и персентил),
дупки в рилевацията, „твърде кръгъл" резултат. **Това са индикатори, не обвинения** —
изискват проверка (сливания, извънредно финансиране, промени на периметъра).

## Разследване „Follow the money" (`forensics`)

Двe части в `data/forensics.json`:

1. **Система** — разбива мита „всяка болница е на минус": съпоставя резултата на
   предприятията с регионалната Gestione Sanitaria Accentrata (GSA, код 000), която
   покрива голяма част от дефицитите. Показва, че истинският дефицит на системата е
   близо до нулата, а част от предприятията са на печалба.
2. **Разходни аномалии** — извлича детайлните разходни редове (CE, секция B) за
   рисковите вектори (доставки, услуги, **консултации/наемен труд**, изнесени услуги,
   **наеми на трети лица**, **покупка на услуги от частни**), нормализира ги (дял от
   разходите, на легло), сравнява с националните връстници (медиана, 90-и персентил,
   robust z-score) и вдига флагове за отклонения и годишни експлозии. Плюс класации.

Отклонение ≠ незаконност — това насочва проверката (Corte dei conti / ANAC).

## Обществени поръчки „Appalti" (ANAC)

`data/appalti.json` (от `fetch:appalti`) агрегира поръчките на здравните възложители:

- **По регион** — 100% надеждно (ключ: sezione_regionale), за сравнение между регионите.
- **По възложител (CF)** — свързва се с болниците само при **точно и еднозначно**
  съвпадение на име+регион (`src/lib/match.js`), за да няма грешно приписване.

Ключов сигнал: **делът на поръчките без реална конкуренция** — „affidamento diretto"
+ „procedura negoziata senza pubblicazione", извън рамковите споразумения (които са
предварително състезани). Води се **делът по брой договори** (устойчив), а стойността
е допълнителна. Всеки CIG се брои веднъж (дедупликация); записи с абсурдна стойност
(>1 млрд €, грешки в източника) се изхвърлят. Класация на регионите и възложителите;
per-болница разбивка по вид процедура и топ договори.

### Дълбоки корупционни сигнали (`fetch:aggiudicatari`)

`data/aggiudicatari.json` свързва CIG-овете с два огромни ANAC датасета (обработени
**поточно**, без да се пишат на диска — 0,8 + 1 GB):

- **Изпълнители (aggiudicatari)** — кой прибира парите: национална класация на
  доставчиците, топ доставчици на всяка болница, **концентрация** (дял на 1-вия);
- **Участници (partecipanti)** — **търгове с един кандидат** (единствената подадена
  оферта): класически сигнал за „gara su misura";
- **Frazionamento** — преки възлагания точно под праговете (35–40k / 130–140k €) и
  **удължавания/подновявания** (proroga/rinnovo) без нов търг.

Всичко това са **индикатори за проверка, не доказателства** (възможни са монопол,
патент, малък пазар, спешност).

## Бележки по данните

- Финансовите данни са на ниво **ente SSN** (юридическото лице): самостоятелните
  болници (AO/AOU/IRCCS) имат собствен отчет; болниците-президии на ASL се
  отчитат във финансите на своята ASL и са изброени в нейния отчет.
- Кодовете `000` (GSA — централизирано регионално управление) и `999`
  (консолидиран регионален отчет) се пропускат — не са болници.
- Сумите са в евро по годишните консолидирани отчети (consuntivo).
- WAF-ът на dati.salute.gov.it отхвърля Node `fetch` (TLS фингърпринт) — за този
  портал пайплайнът минава през системния `curl`.

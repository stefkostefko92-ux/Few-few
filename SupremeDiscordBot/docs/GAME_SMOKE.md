# Server Season — smoke в жив тестов сървър (преди публично включване)

Играта е покрита от unit тестове с mock-ове (backend `game`/`companions`/`minigames`/
`season`/`gameSeasonAdmin`, bot `gameCommands`/`companions`/`minigames`), но никой тест
не говори с реален Discord. Този чеклист е ЕДИН час в тестов сървър, който доказва
пътя „Discord → бот → backend → база → обратно“. Прави се веднъж след първия деплой
на v50 и след всяка промяна по бота/играта. Отмятай с дата и от кого.

## 0. Преди да започнеш (5 мин)

- [ ] Деплоят е минал, `deploy/smoke.sh` е зелен (вкл. проверка 9: картинки + страница на играта).
- [ ] Вътре в контейнера на backend-а:
  ```bash
  docker compose -f /opt/few-few/current/SupremeDiscordBot/docker-compose.yml \
    exec -T backend node scripts/game-smoke.mjs <ID на тестовия сървър>
  ```
  Очаквано: 60 спътника, текущ сезон (S1 се създава сам), картинките сочат `FRONTEND_URL`.
- [ ] Тестов сървър с бота, ≥2 човешки акаунта (улавяне и размяна искат двама), един канал
  за играта, един за counting, един за trivia, един за обяви; една „безопасна“ роля под ролята
  на бота за награда за ниво.
- [ ] Новите команди се виждат в Discord (`/daily`, `/profile`, `/leaderboard`, `/shop`,
  `/companion`, `/quest`, `/trivia`, `/wyr`, `/tod`). Ако не — до ~1 час след старта на бота
  (глобална регистрация) или ръчно `npm run deploy-commands` в контейнера на бота.

## 1. Табло (10 мин)

- [ ] Dashboard → сървър → **Game** → Overview: включи играта, задай канал за обяви,
  counting канал, trivia канал + „weekly“, quest канал + куестове включени. Запази → тост „Saved“.
- [ ] Level roles: добави роля за ниво 1. Shop: създай артикул „Test role“ (ROLE, 10 искри, 1 ден)
  и един CUSTOM за 5 искри.
- [ ] Companions таб: каталог 60, сезон показан с дати. Quests & mini-games таб: няма активни
  куестове още (или един, ако :07 вече е минал).
- [ ] Admin → **Season**: текущият сезон е S1, 4 сезонни спътника; смени името и запази
  (иска свеж втори фактор) → тост, в „All seasons“ името е ново. Върни го.

## 2. XP, ниво, награди (10 мин)

- [ ] Акаунт A пише 3 съобщения в канала на играта през >60 s (охлаждане). До 30 s след третото
  `/profile` показва XP > 0 и „messages“ = 3. Съдържанието на съобщенията НЕ се вижда никъде
  (нито в таблото, нито в базата) — това е обещанието от `DISCORD_VERIFICATION.md` §3.1.
- [ ] `/daily` → искри + XP; второ `/daily` → „come back in …“. Streak = 1.
- [ ] Ако A стигне ниво 1 (100 XP): обява в канала за обяви, ролята за ниво е дадена.
  Ако не — временно свали XP per message на 100 от таблото, напиши едно съобщение, върни го.
- [ ] `/shop` → избери „Test role“ → Confirm → ролята е дадена, искрите намалели. Таблото →
  Shop → „Recent purchases“ показва покупката с дата на изтичане.
- [ ] Гласов канал: A влиза за ≥2 минути и излиза → `/profile` показва voice minutes ≥ 2 (до 30 s).

## 3. Спътници (10 мин)

- [ ] Поява — само по естествен път (не вадиш поява през API: ботът публикува единствено
  своите собствени и една „чужда“ жива поява би блокирала следващата за 5 мин). Правилото:
  ≥6 XP събития след последната поява, после шанс 1/25 на събитие, интервал 12 мин. С 2 акаунта
  и 60 s охлаждане (свали го на 10 s от таблото за теста) ~30 съобщения дават поява в рамките
  на 5–15 мин: embed с картинка и бутон **Catch**. Ако картинката липсва → `FRONTEND_URL`/nginx.
- [ ] A натиска Catch → съобщението става „caught by A“; B натиска (ако успее преди A) → „too slow“.
  Втори Catch от A на друга поява при Free → „collection is full (1)“.
- [ ] `/companion list` → #1; `/companion feed 1 5` → fed 5, искрите намалели; `/companion info 1`
  показва картинката. `/companion trade @B 1 1` (B трябва да има спътник) → B натиска Accept →
  списъците са разменени.
- [ ] Появата изтича след 5 мин без улавяне → „slipped away“, бутонът изчезва.

## 4. Куестове, Counting, Trivia (15 мин)

- [ ] Таблото → Quests → New quest: MESSAGES, target 5, 7 дни → в quest канала има embed с лента.
  5 съобщения от A/B (с охлаждане 60 s — или свали го на 10 s) → лентата се обновява (до 60 s),
  при 5/5 embed-ът става „completed“, пинг към топ приноса, искрите на всички принесли растат.
- [ ] Counting: A пише `1`, B `2`, A `3` → ✅ на всяко. A пише `4` веднага след своето `3` →
  ❌ + „can't count twice in a row“, рестарт. Текст „hello“ в канала → нищо (не се трие).
  Таблото → Quests & mini-games → Counting показва current/record.
- [ ] `/trivia` (Manage Server) в trivia канала → embed с 4 бутона; B отговаря грешно → лична
  бележка; A отговаря вярно → „you were first“, общото съобщение показва отговора и победителя,
  бутоните изчезват. Второ `/trivia` веднага → „a round is already open“ само ако първият не е
  затворен. `/trivia source:KB` при Free → пада на банка (не грешка).
- [ ] `/wyr` при Free → „part of Premium“ бележка; при Premium → embed с 🅰️/🅱️, гласуването сменя
  броя във footer-а. `/tod truth` — същото гейтване.

## 5. GDPR и почистване (5 мин)

- [ ] A: `/privacy info` → броячите на играта присъстват (профил, спътници, покупки).
  `/privacy delete` → редовете на A изчезват; `/leaderboard` вече не го показва; уловените от A
  появи остават като събитие без ID; trivia победата остава без ID.
- [ ] Изгони бота от тестовия сървър → след 30 дни `retention-weekly` чисти всичко за сървъра
  (не чакай — провери само, че `jobs/dataRetention.js` включва game таблиците: да, v50).

## 6. Край на сезона (по желание, 5 мин)

- [ ] Admin → Season: сложи `endsAt` на текущия сезон в миналото (само в тестова среда!).

  ```bash
  docker compose exec -T backend node -e 'import("./src/lib/game/season.js").then(m=>m.closeSeasonIfEnded()).then(console.log)'
  ```

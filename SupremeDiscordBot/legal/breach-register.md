whether any breach was notifiable**. It is referenced by
[`breach-procedure.md`](breach-procedure.md) §11 and [`ROPA.md`](ROPA.md).

> of demonstrating compliance on us, and a supervisory authority asks for this

## Required fields per entry

Every entry must carry all of the following (per `breach-procedure.md` §11):

| Field | Notes |
|---|---|
| Reference | `BR-YYYY-NN` |
| Detected at | UTC timestamp, and how it was detected |
| Nature of the breach | Confidentiality / integrity / availability |
| Categories of data | And approximate volume |
| Categories of data subjects | And approximate number |
| Likely consequences | Assessment of risk to rights and freedoms |
| Measures taken | Containment, remediation, mitigation |
| Notified to supervisory authority | Yes/no + timestamp + reasoning if not (Art. 33(1)) |
| Notified to data subjects | Yes/no + timestamp + reasoning if not (Art. 34) |
| Affected customers notified | Per DPA §7 — within 48 hours of awareness |
| Closed at | And by whom |

An entry is required even when the assessment concludes that notification was
not necessary; the reasoning for that conclusion is itself the record.

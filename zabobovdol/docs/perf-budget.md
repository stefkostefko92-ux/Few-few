# Бюджет за производителност

Лабораторно измерване срещу работещ сървър. **Не са полеви данни** (CrUX) —
след деплой се сверява с `node tools/seo/cwv.mjs <URL>`; при разминаване се
вярва на реалното.

## Пускане

```bash
npm run build && npx next start -p 3100 &      # или BASE_URL към тестов/жив сървър
BASE_URL=http://127.0.0.1:3100 node scripts/perf-budget.mjs [--runs 7] [--json]
```

Изход: `0` в бюджета · `1` над праг · `2` грешка при мерене. Първата заявка
(студен старт) се отчита отделно и не се прага; прагът е върху **медианата** на
топлите заявки (с разсейване в скоби).

## Прагове (променят се с env)

| Страница | HTML (gzip) | TTFB медиана |
|---|---|---|
| `/` | 60 KB (`BUDGET_HOME_KB`) | 800 ms (`BUDGET_TTFB_MS`) |
| `/kak-da` | 190 KB (`BUDGET_KAKDA_KB`) — „да не се влошава“, цел < 60 KB | 800 ms |
| едно ръководство (`GUIDE_PATH`) | 60 KB (`BUDGET_SMALL_KB`) | 800 ms |
| `/uslugi` | 60 KB | 800 ms |
| `/dezhurna-apteka` | 60 KB | 800 ms |

HTML е **пренесеният, компресиран** размер (без компресия на сървъра се
изчислява gzip на суровия HTML). TTFB е от същата машина, без мрежов лимит —
затова прагът е щедър; той хваща регресии (пропаднал кеш, нова бавна заявка),
не заменя Lighthouse.

Пълният бюджет (TBT < 250 ms, CLS < 0.05, FCP < 1.5 s на 4× CPU / Slow 4G)
се проверява след деплой с `node tools/seo/prelaunch-audit.mjs <URL> --runs 3`
и `node tools/seo/cwv.mjs <URL>`.

## Измерено (локално, build + next start, 7 топли заявки)

| Страница | HTML gzip | TTFB мед. преди → след |
|---|---|---|
| `/` | 53.8 KB | 29 → 27 ms (студена 192 → 221 ms) |
| `/kak-da` | 170.8 KB | 83 → 63 ms |
| ръководство | 21.6 KB | 12 → 12 ms |
| `/uslugi` | 44.4 KB | 17 → 16 ms |
| `/dezhurna-apteka` | 23.7 KB | 11 → 10 ms |

Разликите са в шума на споделена машина — мързеливият чат не променя HTML/TTFB
(очаквано). Ефектът е в JS: чънкът на `layout` **27 591 → 23 708 B** (−3,9 KB
суров, −14 %), чатът се тегли след клик или при idle. Бутонът е в сървърния
HTML от първия байт. TBT не е мерен (няма Chromium с throttling тук).

## Кеш на данните

`src/lib/cache.ts` — `unstable_cache` с тагове (`c:faq`, `c:service`, …),
изчистват се от `src/lib/admin/actions.ts` при запис/изтриване/публикуване.
Страниците остават `force-dynamic` (CI билдва с фиктивна база; `revalidate`
на страница би ударило несъществуваща база и би спряло брояча `Faq.views`).
Изтичане: 300 s за съдържание, 60 s за измами/дежурство/прекъсвания.

# Android приложение „За Бобов дол“ (TWA)

Това приложение е **обвивка** на сайта (Trusted Web Activity). Показва живия сайт
`https://zabobovdol.carbonstealth.eu` на цял екран, като истинско приложение, без
адресна лента. Съдържанието винаги е в синхрон със сървъра — нищо не се дублира.

Тук има само конфигурацията (`twa-manifest.json`). Самият Android проект се
генерира и строи с **Bubblewrap** — официалния инструмент на Google.

Има **два начина** да го построите:
- **А) Автоматично през GitHub Actions** (най-лесно — без нищо инсталирано);
- **Б) Ръчно на компютър** с Bubblewrap (по-надолу).

---

## А) Автоматично построяване (GitHub Actions)

Без Android Studio и без Java на вашия компютър.

1. В GitHub отворете раздел **Actions** → **„Android (TWA) build"** → **Run workflow**.
2. Изчакайте да завърши. От страницата на пуска свалете **Artifacts →
   `zabobovdol-android`** — вътре са `app-release-signed.apk` (за инсталация на
   телефон) и `app-release-bundle.aab` (за Google Play).
3. В **Summary** на пуска ще видите **SHA‑256 отпечатъка** — поставете го в
   админ панела → **Мобилно приложение**.

Без допълнителни настройки билдът ползва **временен ключ** (става за тест на
телефон, но **не** за Google Play). За стабилен ключ за Play задайте тези
**secrets** (Settings → Secrets and variables → Actions):

| Secret | Какво е |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore файлът: `base64 -w0 android.keystore` |
| `ANDROID_KEYSTORE_PASSWORD` | паролата на keystore |
| `ANDROID_KEY_PASSWORD` | паролата на ключа (alias „android") |

> Ключът се създава веднъж (виж стъпка 1 по-долу) и се пази на сигурно. Със
> зададени secrets всеки следващ билд ползва същия ключ — както изисква Google Play.

---

## Б) Ръчно построяване — какво е нужно (еднократно)

- **Node.js 18+** и **Java JDK 17** (Temurin/Adoptium).
- Bubblewrap CLI:
  ```bash
  npm install -g @bubblewrap/cli
  ```
  (Bubblewrap сам сваля Android SDK при първото пускане.)

---

## Стъпка 1 — Построяване на приложението

От тази папка (`android/`):

```bash
# Генерира Android проекта от манифеста на сайта.
# Когато пита, потвърждавайте стойностите от twa-manifest.json
# (име „За Бобов дол", package eu.carbonstealth.zabobovdol, цвят #212f8a).
bubblewrap init --manifest https://zabobovdol.carbonstealth.eu/manifest.webmanifest

# Bubblewrap ще предложи да създаде ключ за подписване (keystore).
# ЗАПАЗЕТЕ си keystore файла и паролите на сигурно — нужни са за всяко обновяване!

# Построява подписаните файлове.
bubblewrap build
```

Резултатът е:
- `app-release-bundle.aab` — за качване в **Google Play**;
- `app-release-signed.apk` — за пробна инсталация на телефон.

---

## Стъпка 2 — Вземане на SHA‑256 отпечатъка

```bash
keytool -list -v -keystore android.keystore -alias android
```
Копирайте реда **SHA256** (дълъг низ с двоеточия).

> Bubblewrap често показва отпечатъка и сам в края на `init`.

---

## Стъпка 3 — Свързване със сайта

1. Влезте в **админ панела** → **Мобилно приложение**.
2. Поставете SHA‑256 отпечатъка и натиснете **Запази**.
3. Готово — сайтът вече сервира `…/.well-known/assetlinks.json` с този отпечатък
   и приложението се отваря на цял екран.

> Алтернативно (за технически хора): може да зададете отпечатъците през
> променливата `ANDROID_CERT_FINGERPRINTS` в `.env` (по няколко, разделени със
> запетая).

---

## Стъпка 4 — Публикуване в Google Play

1. Създайте приложение в [Google Play Console](https://play.google.com/console)
   (еднократна такса $25 за разработчиков акаунт).
2. Качете `app-release-bundle.aab`.
3. **Play App Signing** е **задължителен** за нови приложения (Google
   преподписва пакета с production ключ).
4. Play Console показва **още един** SHA‑256 (App signing key certificate) —
   **задължително добавете и него** в админ панела (всеки отпечатък на нов ред).
   Без този отпечатък инсталираното от Play приложение ще показва **URL лента**
   (Play App Signing преподписва пакета). Намира се в Play Console → **Setup →
   App integrity → App signing key certificate**.
5. Попълнете **Data Safety** формата честно: ако сайтът ползва Plausible
   статистика — декларирайте „analytics“; декларирайте и данните, които
   потребители подават през формите (обяви, снимки, сигнали) и достъпа до
   местоположение (по избор). Свържете я с политиката `/poveritelnost`.
6. Попълнете описание, икона и снимки и пуснете за преглед.

> ⚠️ **Нов разработчиков акаунт (регистриран след 13.11.2023):** Google изисква
> **закрит тест (closed testing) с поне 12 тестъра в продължение на 14 поредни
> дни**, преди да отключи production достъп. Планирайте този период; пуснете и
> **Pre-launch report** (Firebase Test Lab) за проверка на сривове/достъпност на
> реални устройства.

## Обновяване на приложението (по-късно)

Сайтът се обновява сам — приложението винаги показва най-новото съдържание, **без
ново пускане**. Нова версия на самото приложение е нужна само при смяна на име,
икона или цвят:

```bash
# Вдигнете "appVersionCode" и "appVersionName" в twa-manifest.json, после:
bubblewrap update
bubblewrap build
```
и качете новия `.aab` в Play.

---

## Бележки

- Push известия НЕ са включени (обвивката не ги поддържа). Ако някога потрябват,
  се минава към хибриден подход (Capacitor).
- Файлове като `android.keystore` и генерираните Android папки **не** се качват в
  Git (виж `.gitignore`).

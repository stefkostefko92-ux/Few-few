# Криптирани бекъпи на базата (само ти можеш да възстановиш)

Тези скриптове правят **автоматичен, криптиран** бекъп на базата (PostgreSQL).
Възстановяване е възможно **само с твоя частен ключ**, който държиш офлайн,
извън сървъра. Дори някой да открадне сървъра и всички бекъп файлове, не може
да ги отвори.

- `backup-db.sh` — създава криптиран бекъп (нужен е само **публичният** ключ).
- `restore-db.sh` — възстановява от бекъп (нужен е **частният** ключ — само ти).

## Защо `age`?

`age` е модерен, прост инструмент за криптиране с двойка ключове
(публичен + частен). Сървърът пази само публичния ключ → може само да
**криптира**. Разкриптирането изисква частния ключ, който е единствено у теб.

---

## 1. Еднократна настройка (прави се веднъж, на ТВОЯ компютър — не на сървъра)

### а) Инсталирай `age`
- **Windows:** `winget install FiloSottile.age` (или изтегли от
  https://github.com/FiloSottile/age/releases)
- **macOS:** `brew install age`
- **Linux:** `sudo apt install age` (или от releases по-горе)

### б) Генерирай двойка ключове
```bash
age-keygen -o backup-key.txt
```
Това създава файл `backup-key.txt`, който съдържа:
- **частен ключ** (редът `AGE-SECRET-KEY-1...`) — ТАЙНА, само за теб;
- **публичен ключ** (реда `# public key: age1...`) — този слагаш на сървъра.

> **Пази `backup-key.txt` като очите си.** Сложи копие на 2–3 сигурни места
> (USB офлайн, мениджър на пароли, принтиран на хартия в чекмедже).
> **Ако загубиш този файл, бекъпите стават безвъзвратно неотваряеми.**
> Не го качвай в Git и не го дръж на сървъра.

### в) Кажи на сървъра САМО публичния ключ
На VPS-а, в папката на проекта (`zabobovdol/`), отвори файла `.env` и сложи
**само публичния** ключ (реда `age1...`):
```bash
AGE_RECIPIENT="age1qz...тук_лепиш_ПУБЛИЧНИЯ_ключ..."
```
Готово — сървърът вече може да криптира, но не и да разкриптира.

## 2. Автоматичен бекъп (вече вграден в Docker) — нищо за правене

В стека има отделна услуга **`backup`**, която тръгва автоматично с
`docker compose up -d`. Тя:

- прави криптиран бекъп **всеки ден в 00:00** (часът е `BACKUP_TIME`,
  по локалното време `BACKUP_TZ`, по подразбиране `Europe/Sofia`);
- пази **последните 31 копия** (`BACKUP_RETENTION_DAYS`, ≈ последния месец) и
  трие по-старите автоматично;
- прави и едно копие веднага при стартиране (`BACKUP_ON_START=true`), за да
  се види, че работи;
- инсталира си `age` сама — няма ръчни стъпки на сървъра.

Файловете се пишат в папка `backups/` до проекта:
`backups/zabobovdol-YYYYMMDD-HHMMSS.sql.gz.age` (+ `.sha256`).

Полезни команди:
```bash
docker compose up -d                 # стартира и backup услугата
docker compose logs -f backup        # следи кога и как минават бекъпите
docker compose exec backup sh -c 'bash /scripts/backup-db.sh'   # ръчен бекъп веднага
ls -lh backups/                      # виж готовите криптирани копия
```

> Съвет: периодично копирай съдържанието на `backups/` и на друго място
> (друг сървър, външен диск, облак). Понеже файловете са вече криптирани,
> можеш спокойно да ги държиш където и да е.

### Алтернатива: cron на хоста (ако не ползваш Docker стека)
```cron
0 0 * * * cd /path/to/zabobovdol && ./scripts/backup-db.sh >> backups/backup.log 2>&1
```
(изисква `age` да е инсталиран на хоста и `AGE_RECIPIENT` в обкръжението/`.env`)

> Съвет: периодично копирай съдържанието на `backups/` и на друго място
> (друг сървър, външен диск, облак). Понеже файловете са вече криптирани,
> можеш спокойно да ги държиш където и да е.

## 4. Възстановяване (restore) — само ти, с частния ключ

Това се прави, когато трябва да върнеш данните. Нужен е **частният ти ключ**.

**Вариант А — през backup контейнера (там `age` вече е наличен):**
```bash
# сложи временно частния си ключ до проекта (напр. backup-key.txt) и:
docker compose exec -e AGE_IDENTITY=/backups/backup-key.txt backup \
  bash /scripts/restore-db.sh /backups/zabobovdol-YYYYMMDD-HHMMSS.sql.gz.age
# след това ИЗТРИЙ ключа от сървъра!
rm -f backups/backup-key.txt
```

**Вариант Б — от твоя компютър (най-сигурно):**
```bash
AGE_IDENTITY=/path/to/backup-key.txt \
  ./scripts/restore-db.sh backups/zabobovdol-YYYYMMDD-HHMMSS.sql.gz.age
```
Скриптът:
1. Проверява контролната сума (цялост на файла).
2. Иска изрично потвърждение (пишеш `ДА`), защото **презаписва** базата.
3. Разкриптира с частния ти ключ, разархивира и зарежда в базата.

След това рестартирай приложението:
```bash
docker compose restart app
```

> Внимание: след restore изтрий частния ключ от сървъра, ако си го качвал
> там временно. Най-добре е restore да правиш от собствения си компютър.

---

## Алтернатива с GPG (ако предпочиташ)

Ако вече ползваш GPG, задай в `.backup.env`:
```bash
GPG_RECIPIENT="твоя@имейл.бг"   # или отпечатъка на публичния ти ключ
```
Импортирай публичния си ключ на сървъра (`gpg --import public.asc`).
Бекъпът ще е `.gpg`; restore изисква частния ти GPG ключ.

---

## Кратко обобщение на сигурността

| Какво | Къде стои | Може да… |
|---|---|---|
| Публичен ключ (`AGE_RECIPIENT`) | на сървъра, в `.backup.env` | само **криптира** |
| Частен ключ (`backup-key.txt`) | само у теб, офлайн | **разкриптира** (restore) |
| Бекъп файлове (`*.age`) | сървър + където пожелаеш | безполезни без частния ключ |

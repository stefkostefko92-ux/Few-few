# Преди пускане — кратък списък за проверка

Това е практичен списък „стъпка по стъпка“ преди да пуснеш сайта на живо
на VPS-а. Минавай го отгоре надолу и слагай отметка (`[x]`) на готовите неща.
Домейн по подразбиране: **zabobovdol.carbonstealth.eu**.

> Подробните инструкции са в [`DEPLOY.md`](DEPLOY.md) и
> [`scripts/README-backup.md`](scripts/README-backup.md). Тук е накратко.

---

## 🚀 Бърз (почти автоматичен) старт

Ако домейнът вече сочи към сървъра (стъпка 1 долу), целият деплой са **две команди**:

```bash
./scripts/setup-env.sh     # генерира .env с всички тайни + age ключ за бекъп
./scripts/deploy.sh        # строи, вдига и зарежда базата (само при първо пускане)
```

`setup-env.sh` ще покаже **паролата за админ** веднъж — запишете си я. И ще създаде
`backup-key.txt` (частния ключ за бекъпа) — **преместете го офлайн и го изтрийте от сървъра**.

После остава само **HTTPS** (стъпка 4) и **попълване на съдържанието** (стъпка 6).
Долу е същото, разписано подробно.

## 1. DNS — насочване на домейна към сървъра

- [ ] Разбери публичния IP адрес на VPS-а.
- [ ] В настройките на домейна `zabobovdol.carbonstealth.eu` направи **A-запис**,
      сочещ към този IP.
- [ ] Изчакай DNS да се обнови (понякога до няколко часа). Проверка:
      `ping zabobovdol.carbonstealth.eu` трябва да връща IP-то на VPS-а.

---

## 2. Тайни в `.env`

Копирай примерния файл и попълни истинските стойности:

```bash
cp .env.example .env
```

- [ ] **AUTH_SECRET** — дълъг случаен низ (приложението отхвърля примерния):
      ```bash
      openssl rand -base64 48
      ```
- [ ] **ADMIN_PASSWORD** — силна парола за първия администратор (мин. 10 знака;
      слаба/примерна парола се отказва от сийда). Задай и **ADMIN_EMAIL**.
- [ ] **POSTGRES_PASSWORD** — силна парола за базата.
- [ ] **AGE_RECIPIENT** — публичният ключ за криптиране на бекъпите. Генерира се
      на ТВОЯ компютър (не на сървъра):
      ```bash
      age-keygen -o backup-key.txt
      ```
      В `.env` слагаш **само публичния** ключ (реда `age1...`). Файлът
      `backup-key.txt` (частният ключ) **се пази офлайн** — без него бекъпите
      стават неотваряеми. Подробно: [`scripts/README-backup.md`](scripts/README-backup.md).
- [ ] (по желание) **SMTP_HOST / SMTP_USER / SMTP_PASS / SMTP_FROM** — за да се
      пращат сигналите по имейл към общината. Без тях сигналите само се записват
      в базата и се препращат ръчно от админ панела.
- [ ] (по желание) **ANTHROPIC_API_KEY** + смяна на `CHAT_PROVIDER="anthropic"` —
      за AI чатбота. Без ключ помощникът работи на правила.
- [ ] (по желание) **NEXT_PUBLIC_PLAUSIBLE_DOMAIN** — ако ползваш Plausible за
      анонимна статистика на посещенията.
- [ ] Увери се, че `NEXT_PUBLIC_SITE_URL="https://zabobovdol.carbonstealth.eu"`.

## 3. Стартиране

- [ ] Вдигни целия стек (приложение, база, бекъп, nginx):
      ```bash
      docker compose up -d --build
      ```
- [ ] Зареди администратора и цялото съдържание (институции, услуги, ръководства,
      транспорт и т.н.) с една команда:
      ```bash
      docker compose exec app npm run db:seed:all
      ```
- [ ] Провери, че сайтът отваря на `http://<IP>` (порт 80), а админ входът е на
      `/admin/login`.

---

## 4. HTTPS (задължително за продукция)

Не оставяй админ панела само на HTTP.

- [ ] Издай безплатен сертификат с готовия помощник (домейнът трябва вече да сочи
      към сървъра — стъпка 1):
      ```bash
      ./scripts/init-letsencrypt.sh
      ```
- [ ] След успех включи HTTPS на ръка (скриптът показва точните стъпки накрая):
      - в `docker-compose.yml` разкоментирай порт `443` и реда за `./nginx/certs`;
      - в `nginx/zabobovdol.conf` разкоментирай блока `server { listen 443 ssl; ... }`
        и пренасочването `80 → 443`;
      - приложи: `docker compose up -d`.
- [ ] Отвори `https://zabobovdol.carbonstealth.eu` — трябва зелено катинарче.

## 5. Бекъп — и ЗАДЪЛЖИТЕЛЕН тест на възстановяване

> Бекъп, който не си пробвал да върнеш, **не е бекъп**.

- [ ] Провери, че бекъпите се правят (услугата `backup` прави едно копие веднага
      при старт, защото `BACKUP_ON_START=true`):
      ```bash
      docker compose logs -f backup
      ls -lh backups/
      ```
      Трябва да видиш файл `backups/zabobovdol-YYYYMMDD-HHMMSS.sql.gz.age`.
- [ ] **Тествай възстановяването** (dry-run — нищо не пипа живата база; нужен е
      частният ти ключ `backup-key.txt`):
      ```bash
      AGE_KEY_FILE=~/backup-key.txt \
        ./scripts/restore-backup.sh backups/zabobovdol-YYYYMMDD-HHMMSS.sql.gz.age
      ```
      Скриптът разкриптира бекъпа и показва таблиците — така се убеждаваш, че
      частният ти ключ работи и файлът е изправен.
- [ ] (силно препоръчително) Направи и реален тест във **временна** база
      (живата остава непокътната):
      ```bash
      RESTORE_CONFIRM=yes AGE_KEY_FILE=~/backup-key.txt \
        ./scripts/restore-backup.sh backups/zabobovdol-YYYYMMDD-HHMMSS.sql.gz.age
      ```

## 6. Съдържание — попълване на празните чернови

Прегледай и попълни в админ панела (повечето записи са заредени като чернови от
сийда):

- [ ] **Аптека** — работно време и телефон.
- [ ] **Социално подпомагане** — данни за връзка и приемни дни.
- [ ] **Аварии** — телефони за **ток** и **вода**.
- [ ] **Facebook линк** — в админ панела → **Настройки** (показва се във футъра).
- [ ] **Такси** — потвърди телефонните номера.
- [ ] **Автобусно разписание** — потвърди часовете.
- [ ] **Галерия** — качи първите истински снимки.

---

## 7. Финална проверка

- [ ] Сайтът отваря по **HTTPS** без предупреждения.
- [ ] Админ вход на `/admin/login` работи с новата парола.
- [ ] Тест на форма — пусни пробна **обява** и пробен **сигнал**; провери, че
      пристигат в админ панела (и по имейл, ако си настроил SMTP).
- [ ] **Мобилен изглед** — отвори сайта на телефон; менютата и формите работят.

Когато всички отметки са сложени — сайтът е готов за хората. 🎉

# Сигурност — ChatChat

Уязвимост: по общия процес на репото (коренният `SECURITY.md`, coordinated disclosure). Не отваряй
публичен issue с подробности.

## Данни

| Вид                               | Къде       | Бележка                                                                                                         |
| --------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------- |
| Акаунти (имейл, име, роля, фирма) | PostgreSQL | паролата — само Argon2id хеш; служебни данни на техници                                                         |
| Сесии                             | PostgreSQL | в базата е HMAC-SHA256 на токена (`SESSION_PEPPER`), не токенът                                                 |
| TOTP тайни (втори фактор)         | PostgreSQL | AES-256-GCM с `MFA_ENC_KEY` (само на сървъра); смяна на ключа обезсилва всички TOTP                             |
| Линкове за парола                 | PostgreSQL | HMAC на токена; еднократни, 24 ч (нулиране) / 72 ч (нов акаунт); токенът е само във `#` на линка                |
| QR етикети на таблата             | PostgreSQL | HMAC на токена в `Device.qrTokenHash`; нов етикет обезсилва стария                                              |
| Запазени филтри                   | PostgreSQL | само позволените полета на обхвата (zod `.strict()`), без лични данни                                           |
| Случаи, съобщения, AI отговори    | PostgreSQL | технически данни за таблото; въпросите са свободен текст — може да съдържат лични данни, ако техникът ги напише |
| Документация на клиента           | PostgreSQL | собственост на клиента; видима по аудитория (PORTAL/INTERNAL/ENGINEERING)                                       |
| Одит                              | PostgreSQL | верига с хешове; само идентификатори и кодове, без съдържание                                                   |
| Логове                            | journald   | pino, без съдържание на въпроси/отговори, имейли, IP и токени (`redact` като втора линия)                       |

Въпросът и избраните откъси от документацията се изпращат към Claude през Google Vertex AI в ЕС
(`VERTEX_REGION` = `eu` или `europe-*`; друг регион → процесът не стартира). Без GCP проект AI е
изключен — няма резервен доставчик.

## Защити

- **Изолация:** всяка заявка носи `tenantId`; порталният техник вижда само своите случаи и таблата на
  своята фирма; чужд обект = 404. Документите — по аудитория на ролята, в портален случай само PORTAL.
- **Сесии:** httpOnly + SameSite=Strict + Secure (продукция) бисквитка; сесията се отнема веднага
  (изход, деактивиране, смяна на роля/фирма, изтекъл срок, нова парола, нулиран MFA, изтриване — AC-16,
  `revokeUserSessions` + кука `onSessionsRevoked` за realtime потоците). Вход с еднакво време с/без
  акаунт; лимит 10 опита / 15 мин / IP.
- **Втори фактор (TOTP, RFC 6238):** задължителен за персонала (поддръжка, инженеринг, знание,
  администратори); без него сесията стига само до `/auth/me`, `/auth/logout`, `/auth/mfa/*`. Включването
  иска паролата (открадната сесия не си „включва“ MFA сама); 5 грешни кода / 15 мин на човек → 429;
  приет код не минава втори път (пазачът е в паметта на процеса — при рестарт ≤ 90 s прозорец).
  Персоналът не изключва TOTP сам — изгубено устройство = `reset-mfa` от администратора или
  `npm run user:reset` с `RESET_MFA=1` на сървъра. Техниците — по желание.
- **Пароли:** никога не се показват, не се пращат и не минават през средата на CLI — администраторът
  получава еднократен линк `/reset#<токен>` и го предава на човека; новата парола отнема всички сесии.
  Администраторът може да издаде линк и на колега със същия ранг — всяко издаване е в одита.
- **Управление на акаунти (FR-22):** само в своя клиент (чужд акаунт = 404), не себе си (роля, активност,
  срок, изтриване), не по-висок ранг и не роля над своята; всяко действие е в одита с причина
  (маскирана с `redactPii`, до 500 знака — без лични данни в причината). Масовите действия са по
  подразбиране само преглед на броя (`dryRun`).
- **CSRF:** synchronizer token в хедър `x-csrf-token` + проверка на Origin + SameSite=Strict.
- **Заглавки:** строг CSP без inline (`script-src 'self'`), `frame-ancestors 'none'`, `Referrer-Policy`,
  HSTS от Nginx; API отговорите са `Cache-Control: no-store`.
- **SQL:** само Prisma и параметризиран `$queryRaw`; пълнотекстовата заявка се строи само от букви/цифри.
- **Лични данни в свободен текст:** имейл, телефон, IBAN, карта и codice fiscale се маскират преди
  запис и преди модела (`src/domain/pii.ts`); UI казва „без лични данни“.
- **AI:** документите са недоверени данни (маркери със случаен жетон); инструментите на модела са само за
  четене и не приемат tenant/модел/аудитория; изходът минава zod + детерминистичен Safety Gate, който третира изхода на модела като враждебен
  (свободният текст също минава през речника; обфускация с невидими знаци/хомоглифи се сгъва).
- **Одит:** вход, изход, случаи, тикети, AI отговори (ниво на доказателствата, решения на gate, снимка
  на знанието, версия на промпта), всички промени по знанието, всички действия върху акаунти.
  Администраторът на клиента (работодателят) НЕ вижда входовете/изходите/MFA проверките на хората —
  това би било дистанционен контрол на служителите (чл. 4 Statuto dei Lavoratori); целта на одита е
  сигурността, не оценка на работата. Вижда ги само администраторът на платформата.
- **Портал:** порталният техник вижда ролята на служителя на производителя, не името му.

## Права на субекта (GDPR чл. 15/17/20)

- **Достъп/преносимост:** `GET /api/v1/admin/users/:id/export` (администраторът на клиента, по искане) —
  JSON с профила, метаданните на сесиите (без токени), написаното от човека (съобщения, тикети,
  обратна връзка, съобщения в разговори), известия, присъствие, запазени филтри. Изнасянето е в одита.
- **Изтриване:** `POST /api/v1/admin/users/:id/erase {reason}` = анонимизация: име „Utente rimosso“,
  имейл `erased-<id>@invalid`, парола, която никой не знае, деактивиран, без TOTP и последен вход;
  сесиите, линковете, известията, присъствието и филтрите се изтриват. Техническото съдържание на
  случаите остава (данни на клиента за таблото), авторът е псевдонимен id без име и имейл.
- **Одитната верига не се пипа** при изтриване: изтрит или променен ред чупи веригата. В нея има само
  идентификатори и кодове (без имена, имейли, съдържание) — след анонимизацията id-то вече не води до
  човек. Срок за самата верига — отворен въпрос (по-долу).

## Отворено (преди продукция)

- Сроковете за ретенция (механизмът е `npm run retention`: сесии 30 дни, затворени случаи след
  `RETENTION_CASE_DAYS`) — определя ги администраторът; одитната верига няма срок (изтриване на ред чупи
  веригата — нужен е дизайн с изтриваеми сегменти).
- Информацията по чл. 13/14 GDPR — текстът е на администратора; връзката се задава с
  `PRIVACY_POLICY_URL` и се показва на входа и във футъра.
- Федеративен вход (OIDC, Entra ID) за персонала; смяна на `MFA_ENC_KEY` без загуба на TOTP (сега:
  нов ключ = всички настройват MFA отново); последната приета TOTP стъпка в базата при няколко копия.
- Договор за обработка (DPA) с Google Cloud за Vertex AI; информация по чл. 13 GDPR за техниците;
  DPIA при нужда (§15.2).
- Антивирус и проверка на MIME при прикачени файлове — преди да се включат (F2).
- Тест за проникване преди go-live (§15.1).

Тайните (`DATABASE_URL`, `SESSION_PEPPER`, `MFA_ENC_KEY`, GCP service account) живеят само на сървъра
(mode 600).

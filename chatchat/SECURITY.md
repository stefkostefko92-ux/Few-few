# Сигурност — ChatChat

Уязвимост: по общия процес на репото (коренният `SECURITY.md`, coordinated disclosure). Не отваряй
публичен issue с подробности.

## Данни

| Вид                               | Къде       | Бележка                                                                                                         |
| --------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------- |
| Акаунти (имейл, име, роля, фирма) | PostgreSQL | паролата — само Argon2id хеш; служебни данни на техници                                                         |
| Сесии                             | PostgreSQL | в базата е HMAC-SHA256 на токена (`SESSION_PEPPER`), не токенът                                                 |
| Случаи, съобщения, AI отговори    | PostgreSQL | технически данни за таблото; въпросите са свободен текст — може да съдържат лични данни, ако техникът ги напише |
| Документация на клиента           | PostgreSQL | собственост на клиента; видима по аудитория (PORTAL/INTERNAL/ENGINEERING)                                       |
| Одит                              | PostgreSQL | верига с хешове; само идентификатори и кодове, без съдържание                                                   |
| Логове                            | journald   | pino, без съдържание на въпроси/отговори, имейли, IP и токени (`redact` като втора линия)                       |

Въпросът и избраните откъси от документацията се изпращат към Claude през Google Vertex AI в ЕС
(`VERTEX_REGION` = `eu` или `europe-*`; друг регион → процесът не стартира). Без GCP проект AI е
изключен — няма резервен доставчик.

## Защити

- **Изолация:** всяка заявка носи `tenantId`; порталният техник вижда само своите случаи и таблата на
  своята фирма; чужд обект = 404. Документите — по аудитория на ролята, в портален случай само PORTAL.
- **Сесии:** httpOnly + SameSite=Strict + Secure (продукция) бисквитка; сесията се отнема веднага
  (изход, деактивиране, изтекъл акаунт). Вход с еднакво време с/без акаунт; лимит 10 опита / 15 мин / IP.
- **CSRF:** synchronizer token в хедър `x-csrf-token` + проверка на Origin + SameSite=Strict.
- **Заглавки:** строг CSP без inline (`script-src 'self'`), `frame-ancestors 'none'`, `Referrer-Policy`,
  HSTS от Nginx; API отговорите са `Cache-Control: no-store`.
- **SQL:** само Prisma и параметризиран `$queryRaw`; пълнотекстовата заявка се строи само от букви/цифри.
- **AI:** документите са недоверени данни (маркери със случаен жетон); инструментите на модела са само за
  четене и не приемат tenant/модел/аудитория; изходът минава zod + детерминистичен Safety Gate.
- **Одит:** вход, изход, случаи, тикети, AI отговори (ниво на доказателствата, решения на gate, снимка
  на знанието, версия на промпта), всички промени по знанието.

## Отворено (преди продукция)

- Ретенция на съобщения, сесии и одит (срокове с администратора на данните) и права на субекта.
- MFA / федеративен вход (OIDC, Entra ID) за персонала.
- Договор за обработка (DPA) с Google Cloud за Vertex AI; информация по чл. 13 GDPR за техниците;
  DPIA при нужда (§15.2).
- Антивирус и проверка на MIME при прикачени файлове — преди да се включат (F2).
- Тест за проникване преди go-live (§15.1).

Тайните (`DATABASE_URL`, `SESSION_PEPPER`, GCP service account) живеят само на сървъра (mode 600).

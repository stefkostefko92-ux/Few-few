# SECURITY — erp-ascensori

Политика на продукта (допълва root `SECURITY.md` на монорепото).

## Модел на заплахите и контроли

- **Автентикация**: bcrypt (10 rounds); пароли невъзстановими — само reset.
  Блокада 5 неуспеха / 15 минути; броячът се нулира при успешен вход.
  Rate limit на `/api/auth/*` по IP.
- **Сесии**: къс JWT access token (HttpOnly, SameSite=Lax, Secure в продукция)
  + refresh token с ротация; в базата стои само SHA-256 отпечатък; нулира се
  при logout и при деактивиране на потребителя → сесията е невъзстановима.
- **Оторизация**: 7 йерархични нива; **сървърна проверка на всяка заявка**
  (`richiedeRuolo`). Изтриване на потребители — само MASTER. Икономически данни
  (fatture, fatturato) — DIREZIONE+. Multi-tenant: изтекъл абонамент → 402.
- **Audit**: неизменим регистър; всяка редица подписана HMAC-SHA256 с ключ,
  известен само на сървъра; никакви маршрути за промяна/изтриване; проверка на
  целостта през `/api/audit/verifica` (ADMIN+).
- **Вход/изход на данни**: Zod валидация на всяко тяло; Prisma (параметризирани
  заявки — без SQL инжекция); еднакъв отговор при непознат имейл/грешна парола
  (без user enumeration); изгаряне на bcrypt време при непознат имейл (timing).
- **Хедъри**: X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy.
- **Content-Security-Policy** (`src/lib/csp.ts` + `src/middleware.ts`): строга,
  с **nonce на всяка заявка** и `'strict-dynamic'`; без `'unsafe-inline'` за
  скриптове. `object-src`/`base-uri`/`frame-ancestors`/`frame-src` = `'none'`,
  `form-action 'self'`, `connect-src 'self'` (доставчиците на AI се викат от
  сървъра). Разхлабено е САМО `style-src-attr` — React и графиките пишат стил
  като атрибут; вмъкнат `<style>` таг пак се блокира. Заради nonce-а страниците
  се рисуват динамично: предрисуван HTML би носил nonce от времето на билда.
  Нарушенията се броят на `/api/csp-report` → метрика `erp_csp_violazioni_totale`
  (само име на директива и произход — без път, без заявка, без запис в базата).
  `CSP_REPORT_ONLY=1` превключва в наблюдение при въвеждане у клиент.
  Обхватът е честен: политиката спира скрипт, вмъкнат в HTML-а, а не нападател,
  който вече изпълнява код — тя е ВТОРАТА преграда, първата е екранирането.
  Проверява се в браузър (`tests/e2e/csp.spec.ts`): всяко нарушение е провал.
- **Фискална защита**: издадени фактури не се трият (само сторно); FK пази
  референцирани анагрифики; изтриване = деактивиране.

## Тайни

`SESSION_SECRET`, `AUDIT_HMAC_KEY` (различни, ≥32 знака, генерирани случайно):
живеят само на сървъра (mode 600), никога в репото/архива. Ротация на
SESSION_SECRET сваля всички сесии; ротация на AUDIT_HMAC_KEY прави старите
подписи непроверими — документирай момента на ротация.
